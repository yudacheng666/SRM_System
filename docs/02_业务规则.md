# 02 业务规则

> 本文档只记录已经确认、需要开发长期遵守的业务规则。详细产品说明见 `01_产品需求PRD.md`。

## A. RFQ

1. RFQ 是询比价主流程标识。
2. 已发 RFQ 的实质修改必须形成 Revision，不覆盖旧版本。
3. 每一 RFQ 行有稳定 RFQ Line ID；物料编码不是 RFQ 行主键。
4. Coverage < 100% 仍允许生成供应商询价包。
5. 未分配物料继续保留在当前 RFQ。

## B. 物料录入

6. 支持单条、剪贴板、文件导入。
7. 导入必须先预览。
8. 剪贴板/CSV/TXT 第一行必须是标题，物料导入精确含“物料编码”；Tab/CSV 分列，普通空格不分字段。
8. Clipboard/CSV/TXT must start with headers and item imports must contain the exact “物料编码” header; parse Tab/CSV fields, never ordinary spaces.
9. 列可乱序、可省略可选字段；空字段保留位置，缺少主键标题拒绝，先预览再提交。
9. Columns may be reordered and optional headers omitted; preserve empty cells, reject missing key headers, and preview before commit.
10. 非法数字不得自动变成 0 或 1。

## C. 供应商分配

11. 物料与供应商是多对多。
12. 新增关系默认追加，绝不隐式覆盖。
13. 供应商视角勾选框直接表示关系。
14. 支持复制另一供应商范围再调整差异。
15. 有添加能力原则上必须有对应移出能力；涉及审计历史时使用取消/作废而非物理删除。

## D. 清单

16. 搜索输入与已应用条件分离，只有点击搜索才生效。
17. 多条件默认 AND。
18. 多选清单统一提供全选/本页全选/反选/本页反选/Shift 连选。
19. 分页提供数字页码。

## E. 图纸和询价包

20. 正式图纸主要为 PDF，可多页、一物料多 PDF。
21. RFQ 生成时按供应商物料范围自动收集对应 PDF。
22. 生成前检查缺失附件。
23. 历史 RFQ 保存当时发出的附件快照。
24. 供应商输出单位为“询价 Excel + 对应 PDF 图纸”的询价包，可 ZIP。
25. 供应商 ZIP 只包含该供应商对应的询价 Excel 和已确认关联的 PDF 原件，不包含内部图纸关联清单、其他供应商资料或内部 ERP 附加字段。
26. PDF 原始文件名原则上保留；同一供应商包内出现不同内容但有效文件名冲突时，应拒绝导出并提示，不得静默覆盖。

## F. 报价证据

27. 有邮件时，以原始邮件及原始附件作为报价来源证据。
28. 无邮件时，可用聊天截图、单独 PDF/文件等原始凭证。
29. 无法可靠识别时采购员可手工录入，但不得丢失原始凭证/说明。
30. 结构化报价数据与原始证据是两层，不互相替代。

## G. 报价导入

31. 报价支持单条、剪贴板、CSV/TXT、Excel。
32. 正式 Excel 允许字段映射和模板复用。
33. 报价表头必须含“RFQ Line ID”或“物料编码”；优先按 RFQ Line ID，缺失时只允许唯一物料编码回退。
33. Quote header must contain “RFQ Line ID” or “物料编码”; prefer Line ID and fall back to an item code only when uniquely matched.
34. 原始值和标准化值并存。
35. 草稿可修正，已确认提交不可覆盖修改。

## H. 报价轮次

36. Round 表示议价阶段。
37. Revision/Submission 表示同一 Round 内的更正提交。
38. 新 Round 不覆盖旧 Round。
39. 新 Revision 不覆盖旧 Revision。
40. 后轮可以只针对部分物料。
41. 每轮保存自己的应报价范围快照。

## I. 报价覆盖

42. 区分：已报价、明确未报价、不供货、漏报、多报、重复、数据错误。
43. 明确未报价不等于漏报。
44. 多报/重复/数据错误不能直接成为有效报价。
45. 后轮漏报不得自动回退上一轮价格。

## J. 沿用上轮

46. 只有采购员明确确认供应商维持原条件时才记录“沿用上轮”。
47. 只处理本轮议价范围。
48. 不得跨过“不供货/未报价”去恢复更早价格。
49. 同价再次报价仍保存为新轮次，降幅为 0。

## K. 阶梯价

50. 阶梯价是报价行的可选价格结构。
51. 完整阶梯必须保留。
52. 重叠、反向、非法价格必须报错。
53. RFQ 数量不落任何档位时为“无适用价格”，不得猜最近档。
54. 比价和轮次变化按 RFQ 数量对应的适用档位计算。

## L. 比价与总价

55. 默认选择最低有效报价，但采购员可以改选。
56. 选择非最低价必须填写原因。
57. 缺报价不得按 0；明确有效报价为 0 与未报价是不同状态。
58. 供应商自身报价总额不能直接当作公平横向比较。
59. 同范围总价必须基于相同物料集合；采购员主动选择至少两家供应商组成比价组，按该组供应商共同有效报价的 RFQ Line ID 集合计算，不默认使用整份 RFQ 的全部供应商交集。
60. 少于两家供应商时不计算同范围总价；选够两家但没有共同有效报价时显示“无可比项目”，不输出 0 元总价。
61. 逐行金额按适用单价 × RFQ 数量计算，先逐行四舍五入到人民币分再汇总；保留原始单价精度。
62. 总价计算前应考虑币种、税口径、单位、数量的可比性。
63. 支持理论最低总额和采购员最终选择总额。

## M. 历史

62. M5 起永久保存每轮、每修订报价。
63. 已确认历史不物理覆盖。
64. 已有报价历史的物料/供应商不能直接删除导致孤儿数据。
65. M7 负责历史分析界面，不是从 M7 才开始存历史。

## N. 历史补录

66. 上线前可导入历史订单、询价和报价。
67. 有什么证据导入什么层级，不编造历史 RFQ/轮次。
68. 未知轮次标记 legacy / 未知轮次。
69. 迁移保留来源、批次、原始值、映射结果和异常日志。

## O. 开发治理

70. M0 是业务交互和数据语义验证，不是正式持久化程序。
71. M0 通过后仍可发现问题；错误直接修复，架构/数据模型变更必须做影响分析，普通新功能进入后续 Backlog。
72. 已确认核心规则若后续修改，应留下变更记录，不允许静默改变。
73. 开发默认在草稿分支；未经用户明确最终确认不得合并 main。
74. 仓库所有示例和测试数据必须虚构/匿名。

## P. 2026-10-08 确认规则
## P. Confirmed rules — 2026-10-08

75. 同编码需求仅在名称、单位、分类以及技术/交付条件兼容时合并数量，保留来源需求行；冲突必须人工确认，不允许静默合并。
75. Consolidate quantities for same-code demands only when names, units, categories and technical/delivery conditions are compatible; retain source rows and require review for conflicts.

76. 合并只影响未发生不可逆业务确认的询价行；已确认报价或已发询价包不能被悄悄改变。
76. Consolidation must not silently change issued inquiry packages or confirmed quotations.

77. 所有主数据录入在后续 M1–M3 支持按唯一关键字段自动补齐，未命中或多候选提示，不覆盖已手工修改的交易字段。
77. Master-data entry must support unique-key autofill in M1–M3; unknown or ambiguous matches require review and user-edited transaction fields are protected.

78. RFQ Line ID、物料编码、图纸各占独立表格列；默认最新新增在前，支持多字段稳定排序。
78. RFQ Line ID, item code and drawing each have separate aligned columns; default newest-first with stable multi-field sorting.

79. 所有搜索框有明确搜索/清空操作，输入状态与生效状态分离；所有可多选列表有取消选择功能，且不删除业务关联。
79. All search areas have explicit Search/Clear actions and draft/applied separation; all multi-select lists support Clear Selection without removing business relationships.

80. 物料剪贴板第一行必须精确出现“物料编码”标题；报价剪贴板第一行至少有“RFQ Line ID”或“物料编码”标题；第二行起是数据。
80. Item paste requires the exact “物料编码” header; quote paste requires “RFQ Line ID” or “物料编码”; records start on the second row.

81. 表头驱动字段映射；允许列顺序变化和非必需列缺失，禁止因空值左移，普通空格永不用于拆列。
81. Imports map by headers, tolerate reordered and omitted optional columns, preserve blanks, and never split on ordinary spaces.

82. 状态采用清楚的中文业务词汇；价格有效且状态列缺失可识别为正常报价，价格和状态均缺失则待检查，非法状态不可写入。
82. Use readable Chinese status labels; a valid price with no status column means quoted, missing both price and status requires review, and invalid statuses cannot be committed.

83. 报价轮次界面显示“第N版”，内部继续保存不可覆盖的 Revision。
83. Quotation rounds display “Version N” while retaining immutable revisions internally.

84. 供应商当前轮次的漏报项目可导出 CSV，包含用于追踪和催报的身份、数量及单位。
84. Omitted quote lines can be exported as per-supplier, per-round CSV with identity, quantity and unit.

85. 从本轮起，新写/实质修改的正式文档按中文一行英文一行；代码保留中英双语模块、函数和关键业务规则注释。
85. New and materially updated official documents use paired Chinese/English lines; code includes bilingual module, function and critical-rule comments.
