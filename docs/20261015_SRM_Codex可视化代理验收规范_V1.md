# 20261015 SRM Codex Buyer-Style Visual Acceptance V1

## 1. 目标和原则 / Goal and Principles

- 用户希望由 Codex 代替采购员完成绝大部分操作测试，不要求用户逐轮人工试用。
- The user wants Codex to perform most buyer-style operational testing, without routine manual user runs.
- **不要机械重复 GitHub Actions 已完整通过的 Python/Node/Playwright 套件。** GitHub CI 负责固定回归；Codex 负责独立可视化探索与发现盲区。
- **Do not mechanically rerun the full passing GitHub Actions suite.** CI handles fixed regressions; Codex explores the real interface and looks for uncovered UX/functionality gaps.
- 用真实浏览器在隔离数据目录中启动 SRM，按真实采购员思路点击、输入、滚动、上传、预览、下载并检查结果；允许用临时脚本协助操作，但禁止修改仓库业务代码、测试源文件或 CI 配置。
- Start SRM with an isolated data root and drive a real browser as a buyer; click, type, scroll, upload, preview, download and inspect results. Temporary automation is allowed, but repository application/test source and CI config must not be changed.
- 通过页面可见结果与关键截图评价易用性；数据及 API 读取仅作佐证，不要跳过页面直接调用接口来替代操作。
- Judge usability through actual visible UI states and screenshots; API/DB inspection supports rather than replaces UI actions.

## 2. 标准分工 / Ownership

| 角色 / Owner | 工作 / Responsibility |
|---|---|
| ChatGPT | 需求、交互设计、功能开发、修复应用代码与测试源码，提交 GitHub / design, development, repairs and test code |
| GitHub Actions | 已定义的单元和浏览器回归、测试报告与产物 / existing automated regressions |
| Codex | **独立用户式操作与视觉审查**、超出 CI 的组合操作、界面可用性、异常路径、测试截图与双语报告 / independent exploratory visual buyer testing |
| 用户 / Buyer | 提出需求、审核简明报告和关键截图、批准是否合并；人工试用可选 / business priorities and merge approval; hands-on testing optional |

## 3. Codex 真实操作任务 / Autonomous UI Missions

- M1：打开系统，比较 1440×900、1366×768、760×900 布局，截图检查顶部操作入口、四步流程、横向滚动、窗口缩放后的遮挡与溢出。
- M1: Open real UI at several desktop and narrow viewports; inspect screenshots for navigation, readability, clipping and overflow.
- M2：只根据页面提供的按钮，建立新询价、导入 12 条和 100 条虚构物料、搜索、全选/本页选/反选、分页、编辑、刷新并切换历史询价。
- M2: Using only visible controls, create RFQs, import synthetic 12/100 item sets, search/select/paginate/edit, reload and switch projects.
- M3：导入 3 家虚构供应商，双向多对多分配，改变筛选/选中状态，检查已分配供应商是否丢失、选择状态是否明显，以及覆盖率低于 100% 时能否导出已分配范围询价单。
- M3: Import three synthetic suppliers, operate bidirectional many-to-many allocation and under-100% exports, checking relationships and visible selection feedback.
- M4：上传含可识别及无法识别文件名的虚构 PDF，操作匹配预览、人工指定、多页查看、解除/重新关联，检查图纸原文件名和缺图提示。
- M4: Upload matched/ambiguous synthetic PDFs, inspect preview/manual resolution/multipage display and original-file behavior.
- M5：不同供应商分别导入不同物料范围的多轮报价、阶梯价格与备注，检查漏报异常、价格变化、锁定及同范围比价；导出 XLSX 并检查关键数值与内容。
- M5: Import multi-round partial supplier quotes, tiers and notes; check missing quotes, round/history, comparison and exported values.
- M6：模拟采购员找不到按钮的情况：不依赖源代码定位，尝试从业务首页独立找到 PDF 匹配、供应商导入、S4 备份、报表导出和字段设置；记录需要的点击数、迷惑性文案及布局问题。
- M6: Without source-code shortcuts, discover drawing matching, supplier intake, backup, report and field controls as a new buyer; report confusing labels and excess steps.
- M7：保存后 F5、关闭/重开浏览器、创建多条历史 RFQ，再下载完整 ZIP 并在全新隔离空库恢复；异常与重复恢复只在临时数据上测试。
- M7: Verify save/reload/reopen, multiple RFQs and isolated full ZIP restore; destructive negative cases only on throwaway data.

以上是可探索任务，不是照抄 CI 脚本；按关键路径自行调整次序、探索遗漏的边界组合。
These are exploratory missions, not a replay of CI scripts; choose novel combinations and sequences.

## 4. 必须交付的报告 / Evidence and Outputs

- 每项 M1–M7 标明 PASS/FAIL/SKIP/NOT_IMPLEMENTED、确切提交 SHA、环境及实际交互路径；FAIL 要有页面、操作、预期、实际、复现步骤和优先级。
- Mark status, exact SHA, environment and real UI path for each mission; failures include reproduction, expectation, observed result and severity.
- 各业务阶段至少一张关键截图（界面布局、物料表、分配状态、图纸预览、报价、比价、数据备份）；能录屏或 trace 时附下载证据和有效期。
- Provide key screenshots for layout, item table, allocation, drawing, quote, comparison and backup; link recordings/traces if possible with expiry.
- 主动提出 UI 改进建议，清晰区分“业务缺陷”“易用性问题”“视觉问题”“测试环境限制”；不得把视口切换或 JS 断言冒充人工可视化检查。
- Propose UX improvements and clearly label functional bugs, usability issues, visual defects and environment limitations.
- 不要求把临时截图/ZIP 大量提交 Git；优先使用 GitHub Actions Artifacts 或可供 ChatGPT 阅读的 GitHub 轻量报告及证据链接。
- Avoid large binaries in Git; use existing CI artifacts or lightweight GitHub report/evidence links.

## 5. Windows 专项 / Windows-Specific Coverage

- 云端浏览器能够替代大多数操作试用，但不等价于 Windows 的资源管理器、双击 BAT、原生文件窗口和 Windows PDF 查看器行为。
- Cloud browser testing covers most workflows but cannot prove native Windows Explorer, BAT double-click, file picker or PDF viewer behavior.
- 如果 Codex Windows Computer Use 可用并经过用户许可，使用专门的 Windows 测试目录和隔离 SRM_DATA_DIR 执行上述桌面项目。Windows 主机必须在线、可远程使用；不覆盖现有业务数据。
- If authorized Windows Computer Use is available, use a separate test folder and SRM_DATA_DIR on a reachable Windows host; do not touch existing business records.
- 如果不可用，则相应 Windows-only 项目标注 SKIP，说明剩余风险；**不得因此要求用户逐轮手动测试**。
- Otherwise mark Windows-only checks SKIP and explain residual risk; do not impose routine user testing.

## 6. 执行和合并纪律 / Execution and Merge Discipline

- 当前 UI 分支为 `draft/20261014-ui-v1`，合并目标仅为 `draft/20261013-m1-storage-ui-audit`；`main` 永不自动合并。
- UI branch `draft/20261014-ui-v1` targets only the draft baseline; never auto-merge `main`.
- Codex 仅测试、诊断、编辑/提交双语测试报告及证据索引文档；不得修改业务代码、自动化测试源码、CI 配置，不得自行修复或合并。
- Codex may test, diagnose and write/commit bilingual reports/evidence docs, but must not edit application/test source or CI workflows, implement fixes or merge.
- 先检查确切 SHA 的 GitHub CI 已通过；默认不重新运行同一套回归。可因异常、CI 失败、缺失证据或有针对性的修复而执行必要的单项复验，并说明理由。
- Verify CI has passed for the exact SHA before independent visual exploration. Do not rerun all passing scripts by default. Targeted reruns are allowed when evidence is missing or a fix is being investigated.
- 用户只需审阅结论并批准合并；如要求个人体验则另行安排，不视为标准测试门槛。
- User reviews outcomes and authorizes merges; hands-on trial is optional rather than a default gate.
