## 3. 阻断问题及优先级
## 3. Blocking Issues and Priority

- P0：先修正并测试 PDF 文件名匹配函数 `escapeRegex`，禁止把不可靠匹配自动建立为已确认关系。
- P0: Fix and test the `escapeRegex` matcher before trusting any proposal; no automatic confirmed linkage.
- P0：不要把浏览器 IndexedDB 或浏览器下载提示等同于已完成磁盘备份；先保留现有备份入口。
- P0: Never equate IndexedDB or browser download intent with verified independent backups; retain current exports.
- P0：独立数据库上线前，旧数据必须通过已保存 JSON/完整 ZIP 导出并核验；迁移不可无提示覆盖。
- P0: Verify legacy JSON/complete ZIP before migration; never overwrite existing workspaces silently.
- P1：保存及图纸关联的结果要有明确“已保存/待保存/失败”的状态。
- P1: Show distinct saved, pending, and failed states for business changes and drawing links.
- P1：完整备份需覆盖报价凭证文件或明确提示“仅图纸 PDF”，不能笼统声称包含全部原始证据。
- P1: Complete backup must include quote evidence or clearly state it only covers drawing PDFs.
- P1：补齐真实 XLSX 导入与统一列映射，消除演示按钮与正式按钮混用。
- P1: Add actual XLSX ingestion/mapping and separate demo-only controls from production actions.
- P2：重新组织为“询价列表 → 询价详情（物料与图纸/分配/报价/比价） → 数据与设置”。
- P2: Reorganize into “RFQ list → RFQ details (items/drawings/assignment/quotes/comparison) → data/settings”.

## 4. 本阶段验收规则
## 4. Acceptance Rules for This Stage

- 存储模块先作为独立基础设施实现，不直接改动现有 UI 和浏览器存储。
- Build storage as a separate module first; do not alter the existing UI or browser store.
- 核心测试包括新建、读取、重复编号、修订冲突、事务回滚、重启读取、备份可校验。
- Core tests include create, read, duplicate IDs, revision conflicts, rollback, restart-read, and verified backups.
- 后续将前端持久化适配器切换至本机 API；迁移完成并通过测试之后才能取消浏览器主存储。
- Later route frontend persistence through the local API; retire IndexedDB only after migration validation.
- 此次审计不代表相关功能已完成运行验收。
- This audit does not certify runtime readiness.
