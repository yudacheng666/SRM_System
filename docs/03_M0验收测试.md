# M0 验收测试报告

> 测试日期：2026-09-29  
> 测试对象：`prototype/m0/index.html`  
> 分支：`draft/v1-product-requirements`  
> 结论：**代码级 / 业务逻辑级验收通过；最终 M0 Pass 仍待真实采购员端到端操作验收。**

## 1. 本轮修复范围

本轮基于前一次 M0 验收发现的问题，完成：

- 严格数值校验，取消非法值自动变 0/1
- 剪贴板/文本导入保留空字段列位置
- 批量字段更新不再以普通空格分隔
- 搜索 Draft / Applied 状态分离
- RFQ Line ID 作为 RFQ 行稳定身份
- 同物料编码可存在多 RFQ 行，依靠 Line ID 区分
- 物料/供应商分配关系改为按 RFQ Line ID 管理
- 报价优先按 RFQ Line ID 回导；物料编码不唯一时要求使用 Line ID
- 报价 Round + Revision/Submission 两层模型
- 已确认报价提交锁定，不能直接覆盖修改
- 新 Revision 只能基于本轮最新 Revision 创建
- 后轮议价范围可单独设置
- “沿用上轮”只作用于本轮范围
- 后轮漏报不自动回退旧价
- 不供货/未报价后不得跨轮复活更旧报价
- 阶梯价严格校验：重叠、反向、非法值、无适用档位均报错
- PDF 式多页/多文件预览交互
- 供应商询价包 PDF 附件缺失检查
- 报价字段映射交互
- 报价证据来源字段
- 动态完整比价范围，不再固定前 4 家/前 24 项
- 供应商自身报价范围总额、同物料范围总额、理论最低、最终选择总额
- 已有报价历史时禁止物理删除造成孤儿数据

## 2. 自动回归结果

### 2.1 HTML / JavaScript 结构

- JavaScript 语法：通过
- 重复 HTML ID：0
- Tab 与 Panel 对应：通过

### 2.2 物料导入

测试：

- `304 不锈钢` 普通空格保留：通过
- 中间空字段不导致后续列左移：通过
- 非法数量 `abc`：拒绝，返回校验错误
- 数量 `0`：拒绝，返回校验错误
- Tab 表格数据：通过
- 自动生成 RFQ Line ID：唯一

### 2.3 阶梯价

测试：

- `1-99:100|100-499:90|500+:80`，数量 120 → 90：通过
- 数量 99 → 100：通过
- 只有 `100-499:90`，数量 50 → 无适用价格：通过
- `1-99:100|200+:80`，数量 150 → 无适用价格：通过
- 重叠区间 → 错误：通过
- 反向区间 → 错误：通过
- 非法单价 `abc` → 错误：通过
- 不再存在“找最近一档价格”的兜底逻辑

### 2.4 报价轮次 / 修订

测试：

- Round 2 属于本轮范围但漏报 → 不回退 Round 1：通过
- Round 2 未将某行纳入议价范围 → 该行可继续使用上一适用轮次报价：通过
- Round 2 明确不供货 → 当前有效报价为空：通过
- Round 3 不会跨过“不供货”恢复 Round 1 旧价格：通过
- 同一 Round 的 Revision 2 会覆盖“当前有效视图”，但 Revision 1 历史仍保留：通过

### 2.5 报价导入 / Coverage

测试：

- 正常 RFQ Line ID 报价：通过
- 同一 RFQ Line ID 重复：识别为“重复”
- 范围外行：识别为“多报”
- 无法识别的报价状态：识别为“数据错误”
- 同物料编码对应多 RFQ 行时，仅用物料编码回导：识别为“数据错误”，要求 RFQ Line ID
- 阶梯价无适用档位：识别为“数据错误”
- 明确未报价：正确区分
- 不供货：正确区分

- Round + Revision

- 后轮议价范围编辑
- 动态比价，不再限制前 N 项
- 供应商自身总额 / 同物料范围总额
