## 已写入代码 / Implemented in Development Code

- 新增业务快照差异检测：正式询价停止编辑至少约 2.5 秒后，自动提交一次新的 SQLite 版本；扫描间隔 0.75 秒。
- Business snapshot changes trigger a new SQLite revision after about 2.5 seconds of inactivity; polling occurs every 0.75 seconds.
- 搜索、筛选、切换标签等没有改变实际业务状态时，不生成重复版本；新建正式询价仍能自动首次落盘。
- Pure search, filter and navigation without business changes do not add empty versions; a new buyer workspace is still initially committed.
- 保留手工“保存到本机”按钮，且依赖服务器现有修订版比较、活动询价比较和已确认报价不可改写约束。
- Explicit manual Save remains, using the server's version/active-workspace conflicts and confirmed quote immutability.
- 单独显示自动保存状态：等待修改、正在保存、已保存第 N 版、保存失败；保存失败停止自动重试，避免重试风暴。
- A dedicated status shows pending, saving, committed version or failed; failures suspend automatic retries to prevent retry storms.
- 网络写入期间产生的新修改仍视为未保存，等前一次成功后再触发下一次自动保存。
- Edits made during an in-flight save remain dirty and are eligible for a follow-up commit.
- 尚未确认的行内编辑、导入预览、草稿表单需要原有“确认 / 写入”操作，自动保存不替代业务确认。
- Unapplied inline edits, import previews and form drafts still require normal Confirm/Apply operations.
- 页面离开时如存在未保存修改，触发浏览器可用的离开提醒；意外断电时未提交输入仍可能丢失。
- Browser-supported unload warnings cover pending state, but uncommitted edits may still be lost in a sudden power failure.
- 启动服务器、保存业务、上传 PDF 及每小时定期检查自动备份；有数据变化且距离上次自动备份至少 24 小时时生成。
- Startup, saved business changes, PDF upload and hourly checks trigger backup eligibility; a full ZIP is created only when changed and at least 24 hours from the previous copy.
- 自动备份保留最近 7 份，路径为 \`%LOCALAPPDATA%\SRM-Lite\backups\auto\`，与手动备份目录分离。
- The newest seven automatic archives are retained in \`%LOCALAPPDATA%\SRM-Lite\backups\auto\`, separate from user-generated manual backups.
- 自动备份仍采用 S4 完整 SQLite + PDF ZIP 和哈希核验，不是 JSON 摘要，也不是供应商外发资料包。
- Automatic archives use the complete S4 SQLite+PDF ZIP with integrity verification, neither a summary JSON nor a supplier-facing package.
- 页面可查看最近备份时间和当前份数；服务器 CMD 对后台备份异常输出 WARNING。
- The UI surfaces the latest completed backup and copy count; the CMD logs WARNING when a backup attempt fails.

## Windows 人工验收 / Windows Acceptance Steps

1. 先确保当前测试询价已保存，备份原程序文件夹，再下载该开发分支的**完整最新源码**并解压到新目录。
1. Save current test RFQs, preserve the old program folder and download the **entire latest development source ZIP** into a new directory.
2. 关闭旧 CMD 服务，进入新目录的 \`prototype\m1-lite\` 并双击 \`run_local.bat\`，确认原有询价仍在。
2. Stop the old CMD server, double-click \`run_local.bat\` in the new \`prototype\m1-lite\` and verify old RFQs remain.
3. 在一笔测试询价里完成一次**真正的业务修改**（例如新增一条虚构物料或新供应商）；**不要点击“保存到本机”**。
3. Make one **actual business change** in a test RFQ (for example add a synthetic item or supplier); **do not click manual Save**.
4. 不再操作页面约 5 秒，检查“自动保存”提示出现已保存第 N 版；刷新 F5，确认修改仍在。
4. Stop interacting for about five seconds, verify the autosave indicator shows committed revision N, refresh and confirm the change survived.
5. 只进行搜索、筛选或切换页面，等待约五秒，确认已保存修订号未无故增加。
5. Search, filter and navigate without business modifications; ensure the saved revision does not increment.
6. 检查“自动备份”提示是否已有完成时间及份数，并检查 \`%LOCALAPPDATA%\SRM-Lite\backups\auto\` 中的完整 ZIP。
6. Check the auto-backup status and the complete ZIPs under \`%LOCALAPPDATA%\SRM-Lite\backups\auto\`.
7. 保留 S4 手动完整 ZIP 作为独立保险；仍可使用隔离空白数据目录执行完整恢复测试。
7. Retain a manual S4 full ZIP as an independent safety copy; use an isolated blank data directory for restoration testing.
8. 已确认报价锁定、断网失败、崩溃恢复及多窗口冲突需继续运行自动化及针对性验收，不在目前版本宣称全部通过。
8. Confirmed-quote protection, network failures, crash recovery and multi-tab conflicts remain for regression and targeted acceptance; they are not all claimed as verified.

## 当前限制 / Current Limitations

- 这是本地开发候选版；不能将它视为有正式容灾保障的软件，也不能把未确认输入误认为已自动保存。
- This is a local development candidate, not production disaster recovery; unconfirmed form input is not yet saved business data.
- 已登记 PDF 进入 S4 备份；原始邮件、聊天截图和非图纸报价凭证的上传管理尚待开发。
- Registered PDFs enter S4 archives; raw emails, chat screenshots and non-drawing evidence still need a later feature.
- 后续可在本阶段验收完成后再讨论是否调整 2.5 秒空闲时长、7 份保留数量和正式 UI 样式。
- After acceptance, idle duration, seven-copy retention and final UI styling can be revisited.
