# 20261014 SRM S4 Complete Backup and Safe Restore Development Log V1

## 目标 / Goal

- 把目前本地 SQLite 已保存的询价、供应商、物料、分配、历史报价和历史版本，连同系统已登记的 PDF 图纸原件打包。
- Package saved local SQLite RFQs, suppliers, items, allocations, historical quotations/revisions, plus all registered original PDF drawings.
- 在新电脑或独立空白数据目录恢复，能够重新打开原有询价和 PDF，不允许覆盖现有工作。
- Restore onto a new computer or an isolated blank data root, preserving readable RFQs and PDFs without overwriting existing work.

## 已开发 / Implemented

- \`backend/backup_bundle.py\`：使用 SQLite Backup API 输出一致数据库快照，生成 \`manifest.json\`、\`database/srm.sqlite3\`、\`assets/<sha256>.pdf\` 的 ZIP。
- \`backend/backup_bundle.py\` uses SQLite Backup API to package \`manifest.json\`, \`database/srm.sqlite3\` and hash-addressed PDF entries.
- 每份已登记 PDF 经 SHA-256 和长度校验；创建 ZIP 后重新从 ZIP 验证数据文件哈希，确认才发布。
- Registered PDF size and SHA-256 are checked, and the generated ZIP is re-read and validated before publication.
- 恢复先验证 ZIP 文件集合、数据库哈希/完整性、PDF 哈希、数据库资产索引和历史版本，再向空白目录写入。
- Restore preflights exact ZIP entries, database integrity/hash, PDF hashes, asset metadata and committed revisions before writing into an empty root.
- 发现已有询价或 PDF 的目标目录时，服务端以错误拒绝恢复；没有“覆盖”或“合并”选项。
- Nonempty RFQ/PDF targets are rejected server-side; no overwrite or merge mode exists.
- 本地 API：\`POST /api/backups/full\`，\`GET /api/backups/full/{filename}\`，\`POST /api/backups/full/restore\`。
- Local APIs provide full ZIP creation, protected download and upload/restore.
- \`index.html\` 新增“下载 S4 完整备份”和“恢复完整备份（仅空白数据）”控件；旧 S3 业务模块保留。
- \`index.html\` adds S4 download and empty-root restore controls, retaining existing S3 business workflows.
- \`SRM_DATA_DIR\` 可明确指定隔离测试目录；默认仍是 \`%LOCALAPPDATA%\SRM-Lite\`，不迁移或删除已有资料。
- \`SRM_DATA_DIR\` explicitly selects an isolated test root; the default remains \`%LOCALAPPDATA%\SRM-Lite\`, with no data migration/deletion.

## 安全边界 / Safety Boundaries

- 只包含系统当前实现存储的业务数据和原始 PDF 图纸；未来报价邮件、截图等文件还未加入，不能把 S4 ZIP 当作包含所有外部证据的档案。
- The S4 ZIP includes currently supported database data and original PDF drawings only; future email/screenshot evidence is not yet stored.
- 数据库上限 128 MiB，单份 PDF 上限 12 MiB，最多 2,000 个不同 PDF，完整 ZIP 上限 512 MiB。
- Limits are 128 MiB for SQLite, 12 MiB per PDF, 2,000 distinct PDF files and 512 MiB per ZIP.
- 备份在点击时创建，**尚不具备定时自动备份**；保存业务数据仍需人工点击。
- Backup is created on demand; **scheduled backup and autosave are not implemented**.
- 系统明确区分“供应商外发询价资料包”与“S4 内部恢复备份”，不要向供应商发送含数据库的内部 ZIP。
- Supplier-facing RFQ exports and internal full restoration bundles are separate; never send an internal database backup to suppliers.

## 推荐人工复验步骤 / Manual Acceptance Procedure

1. 先在旧运行目录使用“保存到本机”，确保所有测试操作已保存。
1. Save pending changes in the existing SRM instance.
2. 备份原程序文件，下载开发分支的 **整个最新源码 ZIP**，不要只替换 \`index.html\`：S4 新增了后端模块和接口。
2. Back up the old program folder and download the **whole latest branch ZIP**, not only \`index.html\`: S4 includes a new backend and routes.
3. 停止旧 CMD 服务，使用新版 \`run_local.bat\` 运行；确认原来的测试询价与 PDF 都存在。
3. Stop the previous CMD service and start the updated launcher; confirm existing RFQs and PDFs.
4. 保存当前业务修改后点击“下载 S4 完整备份（SQLite + PDF）”；检查下载 ZIP 文件且提示询价/PDF 数量正确。
4. Save pending edits, click **Download S4 Full Backup**, and check the ZIP and displayed RFQ/PDF counts.
5. 关闭原服务，用临时空目录启动测试实例；选择刚才下载的 ZIP，点击“恢复完整备份（仅空白数据）”。
5. Stop the original server, launch an isolated empty-root instance, select the ZIP and click **Restore Full Backup (Empty Data Only)**.
6. 恢复成功刷新后检查询价、历史报价、关联关系和 PDF 是否保持一致。
6. After reload, check RFQs, quotation history, allocations and PDF previews.
7. 再次选择同一 ZIP 恢复应被拒绝；禁止在已有数据目录执行覆盖恢复。
7. Attempting to restore again must be rejected; never overwrite an existing data directory.
8. 停止隔离测试实例，在普通新 CMD 窗口双击旧/新版启动脚本即可回到原数据目录。
8. Stop isolated instance; start SRM from a new normal CMD/launcher window to return to the original data root.
