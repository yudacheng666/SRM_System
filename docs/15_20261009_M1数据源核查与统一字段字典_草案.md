## 2. 统一命名规则

1. 相同含义优先使用 ERP 的**原始中文字段名**。例如统一使用 `存货编码`、`存货名称`、`所属类别`，不再在 SRM 的正式页面间交替显示“物料编码”“物料名称”“分类”。
> <sub>1. Use exact ERP Chinese names for identical meanings: inventory code/name/category, rather than alternate labels across SRM screens.</sub>

2. 保留历史旧表头为**导入别名**，映射后保留原始列标题与原文件，不覆盖原文件；模糊、多候选或编码冲突必须人工核查。
> <sub>2. Keep old headers as import aliases and preserve originals. Ambiguous or conflicting identities require buyer verification.</sub>

3. **`RFQ Line ID` 不等于 `存货编码`**；一条 RFQ 的两行即使存货编码相同也可能具有不同数量、版本或技术条件。
> <sub>3. RFQ Line ID is an independent immutable line identity, never a substitute for the ERP inventory code.</sub>

4. ERP `主计量`、`计量单位组`、订单 `主单位`、`采购常用单位`、历史表 `单位` 来源不同，现阶段分别保留，未核实换算关系前不能自动转换。
> <sub>4. Keep base, ordering, purchasing and historical units distinct until UOM mappings and conversion factors are confirmed.</sub>

5. ERP `版本号` 是存货属性；RFQ 第 N 版、供应商报价第 N 版属于 SRM 版本，应在内部明确记录对象身份。
> <sub>5. ERP material version, RFQ revision, and supplier quotation revision are distinct business versions.</sub>

6. 英文译文必须另起一行并使用 `> <sub>English…</sub>`。GitHub 引用块为较淡的文字样式，`sub` 显示较小字号，不使用可能被 GitHub 清理的内联字体颜色 CSS。
> <sub>6. English uses a separate GitHub muted blockquote line with smaller subscript text; inline CSS colors are intentionally avoided.</sub>

## 8. 本次已确认的往来单位关系及 M1 范围

**确认 1：** `往来单位编码` 是主档主体身份；`供应商编码` 代表该主体的供应商身份编码。两者基本相同但不强制一致，独立保留并维护对应关系。
> <sub>Decision 1: Keep the counterparty code and supplier-role code as separate mapped attributes even when most values match.</sub>

**确认 2：** 同一往来单位可以同时是客户和供应商。采用“一张往来单位主档 + 多个业务身份”的设计，不复制成两个互不关联的主体。
> <sub>Decision 2: A counterparty may hold customer and supplier roles simultaneously. Use one counterparty entity with multiple roles.</sub>

**确认 3：** M1 先使用供应商基本信息；`联系方式`、`银行信息`、`数据协同设置` 关联表保留结构，业务 UI 与真实子表导入留待后续。
> <sub>Decision 3: M1 uses core supplier attributes. Contact, banking and collaboration child tables are schema-reserved for later phases.</sub>

**关联键规则：** 三个子表的 `所属往来单位编码` 指向主表的 `往来单位编码`；`所属往来单位名称` 是用于核对的显示信息，不作为唯一关联键。子表记录可能多条，不能按一个字段相同就合并；原模板无实际样本，子记录唯一性仍待核实。
> <sub>The child foreign key is 所属往来单位编码 → 往来单位编码. The display name is not a reliable join key. Treat child rows as potentially one-to-many and verify their own identities later.</sub>

**复用及冲突注意：** `所属类别`、`税率%` 在存货和往来单位表均出现，但所属业务对象不同，不可跨实体强行视为同一个数据库字段。`往来单位名称` 也不能简单替换存货主档的 `存货名称`。
> <sub>Identical header text in different domains does not imply a shared database field; preserve item versus counterparty context.</sub>
