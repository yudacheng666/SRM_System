# 01 产品需求 PRD

> 文档状态：SRM V1 当前需求基线  
> 更新日期：2026-09-29  
> 适用阶段：M0 → V1  
> 本文档整合项目对话中已经确认的需求、采购反馈和 M0 复盘结论。后续确认的产品变更应更新本文档；讨论过程保留在对话/PR，本文档只保留当前有效结论。

## 1. 产品目标

建设一个轻量、可离线使用的采购询比价 SRM 工具，聚焦：

```text
RFQ → 询价物料 → 供应商分配 → 供应商询价包
→ 报价回收 → 报价校验/议价轮次 → 比价/总价分析
→ 最终选择 → OA 比价报告 → 历史沉淀
```

V1 不复制完整 ERP，不要求供应商登录 SRM。

## 2. V1 边界

### 2.1 V1 必须覆盖

- 供应商主数据、物料主数据
- RFQ 创建、状态与修订版本
- 多种方式导入本次询价物料
- 物料与供应商多对多分配
- 询价覆盖率检查
- PDF 图纸/技术资料关联与多页预览
- 按供应商生成询价 Excel + 对应 PDF 图纸的询价包
- 多种方式回收报价
- 报价原始证据链
- 报价覆盖检查
- 报价轮次、同轮修订、阶梯价
- 逐物料比价、总价/同范围总价分析
- 最终供应商选择与非最低价原因
- OA 比价报告
- 历史报价/采购价分析
- 上线前历史询价、报价、订单数据迁移
- 本地备份/恢复

### 2.2 V1 暂不做

- 供应商门户/在线登录报价
- 在线竞价/拍卖
- 复杂审批引擎
- 合同、付款、库存、仓储
- 完整 ERP API
- 高级供应商评分
- 多人权限体系
- AI 自动决策
- 单物料多供应商数量拆分

## 3. 核心数据身份

### 3.1 RFQ

RFQ 使用独立编号，例如：

`RFQ-YYYYMMDD-001`

RFQ 可关联项目/设备/需求单，但不强制。

### 3.2 RFQ Revision

已生成/发出的 RFQ 后，如果询价范围、数量、技术条件、图纸等发生实质变化，应形成新的 RFQ Revision。

旧 Revision 不覆盖。

示例：

- RFQ-001 Rev.0
- RFQ-001 Rev.1

历史报价必须能追溯到供应商实际收到的 RFQ Revision。

### 3.3 RFQ Line ID

每一条 RFQ 明细必须有稳定的内部 `RFQ Line ID`。

RFQ Line ID 与 ERP 物料编码分离：

- 物料编码：业务字段，可重复出现在不同 RFQ 行
- RFQ Line ID：当前 RFQ 行的唯一身份，用于报价回导、覆盖检查和历史追溯

报价导入优先按 RFQ Line ID 匹配；物料编码只能作为辅助/兼容线索。

## 4. 本次询价物料录入

支持：

1. 单条输入
2. 剪贴板批量粘贴
3. Excel / CSV / TXT 文件导入

三种方式必须进入同一预览和校验流程。

### 4.1 剪贴板规则

字段分隔：

- 英文逗号 `,`
- 中文逗号 `，`
- Tab

记录分隔：

- 英文分号 `;`
- 中文分号 `；`
- 换行

普通空格绝不作为字段分隔符，避免拆坏 `304 不锈钢` 等字段。

空白字段必须保留位置，不能删除空单元格后导致后续列左移。

### 4.2 数值校验

数量、价格、MOQ、交期等不得使用“解析失败自动变 0/1”的兜底逻辑。

规则：

- 非法数字 → 明确错误
- 空值 → 按字段是否允许为空判断
- 0 → 按业务规则判断是否合法
- 错误数据不得静默写入

## 5. 清单通用交互

### 5.1 搜索

搜索采用两层状态：

- Draft：用户正在输入的条件
- Applied：用户点击“搜索”后实际生效的条件

输入过程中不得因为分页、勾选、重绘而提前应用未确认条件。

支持：

- 全字段模糊搜索
- 每字段独立模糊搜索
- 多字段 AND
- 新增自定义字段自动继承搜索能力

### 5.2 多选

多选清单统一支持：

- 全选：当前筛选结果全部
- 本页全选
- 反选：当前筛选结果全部反转
- 本页反选
- Shift 连选

### 5.3 分页

统一支持：

- 上一页 / 下一页
- 数字页码
- 当前页高亮
- 大页数省略
- 翻页保持已应用搜索条件和选择状态

## 6. 字段与系统设置

M0 演示字段不是生产字段。

正式字段应由：

- ERP 字段
- 采购业务字段
- 报价字段
- 图纸/附件字段
- 可配置扩展字段

共同确定。

系统设置负责：

- 新增/删除自定义字段
- 名称、类型、校验
- ERP 映射
- 显示/编辑/搜索属性
- 核心字段保护

业务页面只处理字段值。

字段值批量更新支持：

1. 对选中记录统一写入一个值
2. 导入“关键字段 + 目标值”表格按关键字段匹配更新

所有批量更新先预览，区分匹配、未匹配、重复、格式错误。

## 7. 询价分配中心

物料与供应商是多对多关系。

### 7.1 供应商池

当前 RFQ 使用采购员主动维护的候选供应商池，不直接展示完整供应商主数据。

支持：

- 搜索供应商
- 添加到当前 RFQ
- 从当前 RFQ 移出
- 历史采购/报价/分类作为推荐线索

推荐只辅助，不自动做最终决定。

### 7.2 两种分配方式

#### 按物料分配供应商

选一批物料，对其追加一个或多个供应商。

新增关系默认是“追加”，绝不覆盖已有供应商。

#### 按供应商分配物料

勾选框本身直接表示关系：

- 勾选 = 已关联
- 未勾 = 未关联

不再增加第二层“临时选择状态”。

### 7.3 降低重复操作

支持：

- 复制另一供应商的物料范围作为起点
- 再增加/取消差异物料
- 批量关联/取消当前筛选范围

### 7.4 Coverage

显示：

- 总询价物料
- 至少分配 1 家
- 仅 1 家
- 未分配

Coverage 低于 100% 仍允许生成询价包。

只生成已分配部分，未分配物料继续留在 RFQ 中。

## 8. PDF 图纸 / 技术资料

PDF 已进入 V1 主流程。

### 8.1 数据模型

支持：

- 一物料多个 PDF
- 多页 PDF
- PDF 类型/名称
- 版本/修订
- 当前有效/已替代状态
- 一个 PDF 被多个物料共享

### 8.2 预览

列表小预览建议显示：

- 第一页缩略
- PDF 标识
- 页数
- 多文件数量

大预览支持：

- 文件切换
- 上一页 / 下一页
- 当前页 / 总页数
- 放大/缩小
- 适应页面/适应宽度

### 8.3 询价包附件

生成供应商询价包时，系统按该供应商实际分配物料自动汇总对应 PDF。

生成前检查：

- 应有 PDF
- 已找到 PDF
- 缺图纸物料
- 共享/重复 PDF

不得悄悄遗漏。

已发 RFQ 应保存当时附件快照；后续图纸升级不得改写历史 RFQ。

## 9. 供应商询价包

输出单位不是单一 Excel，而是“供应商询价包”。

典型结构：

```text
RFQ_xxx_供应商/
├─ RFQ_xxx_供应商.xlsx
└─ 图纸/
   ├─ xxx.pdf
   └─ ...
```

可进一步生成 ZIP，便于邮件/聊天工具发送。

询价 Excel 至少包含：

- RFQ / Revision
- Supplier
- RFQ Line ID
- 物料编码
- 名称/规格
- 数量
- 单位
- 供应商填写的单价、交期、MOQ 等字段

## 10. 报价证据链

供应商不登录 SRM。

报价真实性/来源证据按实际来源保存：

1. 有邮件：原始邮件 + 原始附件
2. 无邮件：聊天截图、单独 PDF/文件等
3. 系统无法可靠识别：采购员手工录入，但仍应关联可用的原始凭证/说明

结构化 Excel 用于数据处理；原始凭证用于证明报价来源、内容和时间。

每次报价提交/修订应记录：

- 来源类型
- 原始证据引用
- 导入/录入时间
- 采购员
- 原始值
- 标准化值

## 11. 报价导入

支持：

- 单条手工输入
- 剪贴板批量粘贴
- CSV/TXT
- Excel

正式 Excel 支持字段映射和映射模板。

报价单可能包含：

- 普通单价
- 阶梯价
- 交期
- MOQ
- 品牌/型号
- 技术备注
- 未报价/不供货状态

导入后允许在“草稿提交”内修正。

已确认提交不能覆盖修改。

## 12. 报价轮次与修订

必须分成两层：

### 12.1 Round

表示议价阶段：

- 第 1 轮：首次报价
- 第 2 轮：二次谈价
- 第 3 轮及以后：继续议价

### 12.2 Revision / Submission

表示同一轮内供应商更正或重新提交。

示例：

```text
Round 1
  Revision 1
  Revision 2（更正）

Round 2
  Revision 1
```

Revision 不能被覆盖删除。

已确认 Revision 锁定；需要更正时创建新 Revision。

## 13. 每轮应报价范围

每个 Round 必须保存“本轮应报价 RFQ Line ID 范围”快照。

- Round 1 默认 = 该供应商实际收到的询价范围
- Round 2+ 可以只针对部分物料谈判
- 后轮范围允许采购员明确调整

覆盖检查只能与“本轮范围”比较，不能简单与整份 RFQ 比较。

## 14. 报价覆盖检查

至少区分：

- 已报价
- 明确未报价
- 不供货
- 漏报：本轮应报但完全缺失
- 多报：不在本轮范围
- 重复
- 数据错误

“明确未报价”与“漏报”必须区分。

多报、重复、格式错误不能直接进入有效报价。

确认提交前显示异常清单。

如果允许带异常确认，必须保留异常状态供后续审计。

## 15. 沿用上轮

后轮缺失项目绝不自动视为价格不变。

只有采购员确认供应商明确维持原条件时，才写入：

`明确沿用上轮`

沿用规则：

- 只作用于本轮应报价范围
- 不能跨过“不供货/未报价”状态去翻更早历史价格
- 必须记录来源轮次/修订
- 同价重新正式提交也应保存为新轮次记录，降幅为 0

## 16. 阶梯价格

阶梯价属于报价行的可选价格结构，不另建一套流程。

示例：

`1-99:100 | 100-499:90 | 500+:80`

必须保存完整阶梯。

校验：

- 数量区间有效
- min <= max
- 阶梯不能重叠
- 价格必须有效
- RFQ 数量必须实际落入某一档，否则显示“无适用阶梯价”，不得猜最近档

比价和轮次变化均按同一 RFQ 数量对应的适用档位计算。

## 17. 报价有效性和历史

每次确认的报价提交永久保留。

保存：

- Round / Revision
- 原始值
- 标准化值
- 阶梯结构
- 未报价/不供货
- 覆盖异常
- 明确沿用
- 手工修正审计
- 日期
- RFQ / Revision
- Supplier
- RFQ Line ID

历史记录不可物理删除。

如果物料/供应商已经产生报价历史，业务范围删除应改为作废/取消参与，而不是直接清除历史数据。

## 18. 比价

逐物料至少展示：

- 当前有效报价
- 最低价
- 第二低价
- 上次采购价
- 交期
- MOQ
- 阶梯价标记及完整阶梯
- 当前轮次/修订
- 报价覆盖状态

默认选择最低有效报价。

采购员可以改选非最低价，但必须填写原因。

## 19. 总价分析

不得把不同报价范围的总价直接当成公平比较。

至少支持：

### 19.1 供应商自身报价范围总额

`有效适用单价 × RFQ 数量` 的总和。

只描述供应商自身报价规模。

### 19.2 同物料范围总价

对参与比较的供应商先求“共同有效报价物料集合”，再用同一集合比较总额。

必须显示共同物料数量/范围。

### 19.3 指定范围总价

采购员自行选择一批物料，在相同范围比较供应商。

缺报价不得按 0。

### 19.4 理论最低总额

每颗物料取当前最低有效报价后的理论总额。

### 19.5 最终选择总额

按采购员最终选择计算，并与理论最低/历史采购金额比较。

### 19.6 可比性

正式版必须处理/提示：

- 币种
- 含税/未税
- 单位
- 数量口径

不可比时不得静默相加。

## 20. OA 比价报告

M6 正式设计并生成。

至少包含：

- RFQ / Revision
- 参与供应商
- 询价物料
- 各轮/各修订报价
- 阶梯价及本次适用价
- 报价覆盖情况
- 上次采购价
- 轮次降价金额/比例
- 总价/同范围总价分析
- 最终选择
- 非最低价原因
- 二次谈价未降价项目
- 异常说明

V1 只需导出报告，不要求直接接 OA API。

## 21. 历史分析

M5 起开始永久保存历史，M7 负责查询/分析体验。

至少支持：

- 单物料历史采购价
- 单物料历史报价
- 物料 × 供应商历次报价
- 各轮议价变化
- 多供应商历史价差
- 供应商参与/覆盖历史
- 价格趋势

## 22. 上线前历史补录

上线前历史迁移遵循：

> 有什么证据，就导入什么层级；不补造无法证明的历史事件。

### 22.1 只有 ERP 订单

导入为历史订单/采购价格，不虚构 RFQ 或供应商报价。

### 22.2 有历史询价/报价证据

按证据导入：

- 历史 RFQ/询价标识
- 供应商
- 物料
- 日期
- 价格/阶梯价
- 交期/MOQ
- 轮次（仅在可确定时）
- 原始证据引用

不知道轮次时标记 `legacy / 未知轮次`。

### 22.3 迁移审计

保存：

- legacy 标记
- 来源类型
- 原文件/证据
- 迁移批次
- 导入时间
- 原始值
- 标准化结果
- 未匹配/重复/错误日志

## 23. 技术原则

M0 可以继续使用单 HTML + 浏览器内虚构数据验证交互。

进入 M1 前必须完成正式本地运行架构决策，重点验证：

- 本地数据库的可靠持久化
- PDF/附件文件访问与目录打包
- 备份恢复
- 断网运行
- 数据升级/迁移
- 浏览器 file:// / IndexedDB 限制

正式 V1 不应把“浏览器临时存储”作为唯一业务数据保障。

## 24. 数据完整性原则

- 任何导入先预览再提交
- 任何非法值不静默纠正
- 已确认历史不覆盖
- 删除涉及历史时改为作废/取消
- RFQ、报价、附件都要版本/快照可追溯
- 总价比较必须在可比口径下
- 缺报价不是 0
- 后轮漏报不是自动沿用
- 所有业务对象使用稳定内部 ID，不依赖显示文本或行顺序

## 25. M0 通过标准

M0 通过不是“页面看起来完整”，而是证明核心业务交互和数据语义不会明显误导采购员。

必须满足：

1. 物料三种录入方式可用，空字段不移位，非法数字不静默兜底
2. 搜索 Draft/Applied 分离
3. 多选/分页/Shift 行为一致
4. 多对多分配追加不覆盖
5. 供应商询价范围预览准确
6. 多页 PDF 式预览和附件缺失检查可验证
7. 报价多方式导入进入统一模型
8. RFQ Line ID 参与报价匹配
9. 报价覆盖状态正确
10. Round 与 Revision 分离
11. 后轮议价范围可设置
12. 已确认报价不能直接覆盖
13. 沿用上轮不跨过未报价/不供货
14. 阶梯价越界/重叠/非法值不会产生猜测价格
15. 比价不受固定前 N 个物料/供应商限制
16. 至少验证自身报价总额、同物料范围总额、理论最低和最终选择总额
17. 删除/移除不能产生孤儿报价历史
18. 核心页面 JavaScript 无语法错误和重复 ID
19. 最后由真实采购员不依赖开发者解释走完整模拟流程

## 26. 仓库与数据安全

仓库内所有：

- 示例
- 测试数据
- 截图说明
- 文档
- 代码注释

必须使用虚构/匿名信息，不得出现真实公司、个人、客户、供应商、产品或内部敏感数据。

开发修改默认进入草稿分支。只有用户明确确认后才能合并主线。
