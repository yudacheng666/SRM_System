# 20261010 M1-B1 核心数据模型、演示隔离与验收记录

> <sub>M1-B1 Lean Workspace Data Model, Demo Isolation and Acceptance Notes</sub>

**范围：B1 是可序列化业务状态的基础，不是采购员可直接上线使用的完整 M1 软件，也未开始自动保存、备份恢复或服务器部署。**

> <sub>B1 establishes a serializable data model only. It does not implement live autosave, portable backup/restore, an operational M1 application or a company server.</sub>

## 一、保留的轻量业务对象

> <sub>1. Essential domain objects only</sub>

规范工作空间只保存本次询价核心业务数据：物料行、候选供应商、询价行—供应商关联、报价轮次/修订、报价明细/阶梯价、已选供应商、非最低价原因、人工选择与复核标识、本次供应商池、同范围比较供应商组，以及少量自定义字段。

> <sub>The workspace covers RFQ lines, supplier choices and assignments, quote rounds/revisions/tiers, awards and rationales, supplier pool, selected comparison group and minimal custom fields.</sub>

字段命名仍按 ERP 已核实字典统一，但**内部 M0 旧数据键暂保留以便兼容**：`items[].id` 对应显示 `存货编码`，`items[].name` 对应 `存货名称`，`items[].cat` 对应 `所属类别`，`items[].qty` 对应 `询价数量`。后续界面层与新 ERP 导入映射采用正式中文字段标题，不需要一次性修改所有旧程序标识。

> <sub>Keep internal M0 keys for compatibility while mapping them to verified ERP labels at import/export/UI boundaries. Do not rewrite all identifiers just to achieve label consistency.</sub>

供应商对象可保留 `counterpartyCode`（往来单位编码）和 `supplierCode`（供应商编码），并支持同一往来单位具有客户和供应商身份；现有 M0 `suppliers[].id` 继续作为独立演示供应商 ID，不自动把两个 ERP 编码强制合并。

> <sub>Supplier records may carry separate counterparty/supplier codes and dual roles. The M0 demo supplier ID remains a distinct synthetic identity.</sub>

## 二、数据格式及隔离

> <sub>2. Workspace format and demo segregation</sub>

规范对象使用 `format:'srm-workspace'`、`schemaVersion:1`、`workspaceId`、`origin`、`revision` 和 `state`。`origin` 只能为 `demo` 或 `buyer`；**正式新工作空间默认物料和供应商均为空**、比价处于实际报价模式，不把 M0 的 1200 条演示数据加入。

> <sub>The versioned envelope distinguishes demo and buyer workspaces. New buyer workspaces start empty with returned-quote mode; M0 synthetic seed is not auto-imported.</sub>

`assignments`、`awards`、`awardReasons` 以显式条目数组写成 JSON；`manualAwards`、`supplierPool`、`selectedCompareSuppliers` 以字符串数组保存。还原时重建为新的 Map/Set，不会直接共享原对象引用。

> <sub>Convert Maps to entry arrays and Sets to string arrays before JSON serialization; hydration creates independent collection instances.</sub>

`captureM0` 只从**明确提供的**来源状态转换数据，`sourceDataKind:'demo'` 不允许捕获为 `buyer`；`parse(...,{requireBuyer:true})` 不接受 `demo` 来源。此措施防止意外混用，不是安全鉴权机制。

> <sub>Explicit origin tagging and a buyer-only import guard prevent accidental demo contamination. These fields are not security credentials or tamper-proof authentication.</sub>

## 三、已经实现的最小校验

> <sub>3. Validation included in B1</sub>

重复 RFQ Line ID、重复供应商 ID、关联到不存在存货行或供应商、报价轮次/版本身份冲突、非数字报价单价、无效工作空间修订号等均拒绝转换。报价行的 `price:null` 可以用于明确无有效价格，不会自动转为 0。

> <sub>Validation rejects duplicate IDs, broken references, conflicting quote revisions, nonnumeric quoted prices and invalid workspace revisions. Missing prices are never converted to zero.</sub>

B1 只检查**单个结构化快照内部一致性**。不宣称能够验证历史版本相对于数据库原记录有没有被修改；真正的“已确认报价不可覆盖”、并发修订号检查及事务提交在 B2 的存储层实现。

> <sub>B1 verifies a standalone snapshot, not immutable history relative to previously saved database state. Revision-aware commits and transactional persistence are B2 responsibilities.</sub>

## 四、交付源码、测试及运行限制

> <sub>4. Source, tests and boundaries</sub>

源码：`src/m1-lite/workspace-core.js`；纯业务函数 `createEmptyWorkspace`、`captureM0`、`validate`、`hydrate`、`stringify`、`parse`。没有网络、IndexedDB、localStorage 或附件写入；支持后续将统一业务对象交给 IndexedDB 适配器或服务器 API。

> <sub>The pure workspace core exports creation, snapshot, validation, hydration and JSON functions. It has no storage/network side effects and can later feed local or server adapters.</sub>

测试：`tests/m1-b1-model.cjs` 使用**匿名虚构数据**测试对象关联与边界条件，`tests/browser/m1-b1.cjs` 在真实 Chromium 中打开原 M0 HTML，捕获运行状态、往返 JSON，并验证不能将演示种子误作正式工作空间。GitHub Actions 工作流为 `.github/workflows/m1-b1-core-model.yml`。

> <sub>Unit tests cover synthetic model fixtures, while Chromium tests capture real M0 memory state and verify demo-to-buyer isolation. CI uses no actual purchasing data.</sub>

已有 M0 `prototype/m0/index.html` **完全不修改**，继续沿用原业务操作和完整回归测试。B1 的模型尚未连接 M0 操作按钮，也不提供“已保存”界面或数据恢复承诺。

> <sub>The approved M0 HTML is unchanged. B1 has no live save button, UI integration or restore promise.</sub>
