# 轻量 SRM V1 开发规划

## 0. 当前状态

- M0：**代码级验收通过，待采购员端到端 UAT**
- 已建立可点击交互原型：`prototype/m0/index.html`
- 当前 M0 重点验证长清单、双向多对多分配、PDF 多页预览、报价回收/覆盖、阶梯价与报价比较交互，不接真实业务数据。

## 1. 开发目标

先完成可本地离线运行的 V1，用于验证核心业务链：

```text
RFQ → 导入拟询价物料 → 供应商分配 → 生成询价单
→ 导入报价 → 比价选择 → 历史沉淀
```

V1 不追求完整 SRM，不重复 ERP、库存、财务、合同、供应商门户等能力。

## 2. 技术原则

- 本地离线运行，正常使用不依赖网络。
- 源码模块化，最终可构建为便于本地使用的静态 HTML 应用。
- UI、业务逻辑、数据访问层分离。
- 本地数据使用 IndexedDB。
- Excel 导入/导出能力随应用离线打包。
- 后续服务器化时，优先替换数据访问层，不重写业务规则。
- 所有仓库示例、测试数据、截图和文档必须使用虚构或匿名信息。

建议分层：

```text
UI
↓
Application / Business Services
↓
Repository / Data Access
↓
IndexedDB
```

## 3. V1 里程碑

### M0 — 交互原型

先验证四个高返工风险交互，不接真实业务数据：

1. 本次询价物料清单（查阅/筛选/图纸预览）
2. 询价分配中心
3. 报价回收导入
4. 报价比较

重点验证：
- 长清单筛选与批量选择
- 本次询价物料支持单条输入、剪贴板批量粘贴、文件导入演示
- 本次询价物料支持批量删除，并同步清理相关分配关系
- 演示字段可新增/删除、自定义字段可批量更新
- 全字段模糊搜索 + 每个字段独立模糊筛选
- 所有复选框型清单统一支持可靠的 Shift 连选，不只局限于物料分配清单
- 物料 → 供应商、供应商 → 物料双向操作
- 供应商视角勾选框直接代表关联状态
- 本次 RFQ 供应商列表由采购员主动添加，并可确认后移出
- 供应商名称/编码模糊搜索
- 复制其他供应商的物料范围作为分配起点，再做差异调整
- 多对多关系追加而不覆盖
- 三态选择：未关联 / 部分关联 / 全部关联
- Coverage 检查
- 报价回收导入交互：识别 RFQ / Supplier / Line ID、字段映射、导入预览、异常提示、报价轮次选择
- 比价横向展示
- PDF 图纸的列表缩略预览、多页大图预览交互、多个 PDF 切换方式
- 图纸附件完整性提示的交互
- 比价默认选择最低有效报价
- 总价分析交互方向：供应商自身报价总额、同物料范围总价、指定范围总价、理论最低总额、最终选择总额

完成标准：核心操作路径无需解释即可完成，不存在明显误覆盖风险；报价回收导入的字段映射、预览、异常确认和报价轮次流程在进入 M5 正式开发前完成交互验证。

### M1 — 数据基础

实现：
- 供应商主数据
- 物料主数据
- 历史采购数据
- 历史数据迁移/补录基础框架（批次、来源、原始值、映射结果）
- PDF 图纸/技术文档元数据模型与本地文件引用
- 图纸版本/修订与有效状态基础字段
- 简单物料分类
- 根据实际 ERP 字段确定生产字段模型与映射
- 可配置扩展字段
- Excel 批量导入
- 导入预览、错误提示、导入日志
- 自定义字段新增/删除
- 选中记录的字段批量更新
- 通用字段级模糊搜索/筛选能力
- IndexedDB 数据层
- 完整备份与恢复

完成标准：数据可导入、查询、关闭应用后保留，并可完整备份恢复。

### M2 — RFQ 与拟询价清单

实现：
- RFQ 流水号
- RFQ 列表与状态
- 新建/编辑 RFQ
- 通过 Excel/文件导入、单条输入、剪贴板批量粘贴建立拟询价物料
- 导入/粘贴预览与重复编码校验
- 搜索、筛选、批量操作
- 项目/设备等作为可选关联字段
- 建立物料 ↔ PDF 图纸/技术文档关联
- 支持一物料多 PDF、共享 PDF、缺失图纸状态
- RFQ 使用时能够解析本次物料对应的图纸集合

业务上不设置拟询价物料数量上限。

完成标准：可从 Excel 建立一份大批量 RFQ，并稳定保存。

### M3 — 询价分配中心

实现：
- 本次候选供应商池
- 按物料分配供应商
- 按供应商分配物料
- 历史采购/历史报价/分类辅助推荐
- 单条与批量追加
- 供应商视角直接勾选/取消关联
- Shift 连选
- 复制其他供应商物料范围后差异化调整
- 三态关联状态
- 批量移除
- 操作结果提示
- 撤销最近批量操作
- Coverage 检查

Coverage 仅提示，不阻止后续生成。

完成标准：复杂多对多分配过程中，新增关系不得隐式覆盖已有关系。

### M4 — 供应商询价包生成

实现：
- 供应商专属询价单逐份预览
- 按供应商拆分已分配物料
- 一键生成供应商专属 Excel
- 根据该供应商物料范围自动收集对应 PDF 图纸/技术文档
- 图纸附件完整性检查：应有、已找到、缺失、共享/重复
- 生成“询价单 + 图纸文件夹”的供应商询价包
- 可选生成单一 ZIP 包，便于邮件/聊天工具发送
- 稳定的 RFQ Line ID
- 保存生成时的图纸/附件快照，避免后续图纸升级改变历史 RFQ
- 未分配物料继续保留
- 支持后续补充分配并再次生成

完成标准：同一 RFQ 可为不同供应商生成内容不同的询价包；每份包只包含其分配物料及相关 PDF，并可追溯到当时实际发送的询价明细与附件版本。

### M5 — 报价导入

实现：
- Excel 报价导入
- 优先利用 RFQ / Supplier / Line ID 自动识别
- 列字段映射
- 保存供应商导入模板
- 原始值与标准化值并存
- 报价轮次 / 议价轮次
- 首轮报价与二次谈价结果分别保留
- 二次谈价允许价格不变
- 未报价 / 不供货 / 部分报价状态
- 导入异常提示
- 从第一笔正式报价开始永久保存所有报价轮次，不在后续覆盖
- 保存原始报价、标准化报价、阶梯价、覆盖异常与手工修正审计
- 为历史报价/询价补录提供 legacy 导入模式，不伪造未知轮次

完成标准：不同列结构的报价表可以经过映射后进入统一报价数据模型，并形成可长期追溯的报价历史。

### M6 — 比价与选择

实现：
- 价格、交期、MOQ 横向比较
- 最低价
- 第二低价
- 上次采购价
- 默认选择最低有效报价
- 报价覆盖率
- 供应商自身报价范围总额
- 多供应商同物料范围总价比较
- 采购员指定物料范围总价比较
- 理论最低采购总额
- 最终选择总额及与理论最低/历史采购金额的差异
- 缺报价不得按 0 参与总额
- 币种、含税/未税、单位等不可比条件提示
- 逐物料选择供应商
- 批量选择适用供应商
- 非最低价选择必须填写原因
- 首轮 / 二轮及后续议价价格对比
- 降价金额与降价幅度
- 价格未变化的二次谈价结果记录
- 正式设计比价报告版式、预览与导出
- 比价报告展示 RFQ 数量、适用阶梯价和完整阶梯报价
- 比价报告包含报价覆盖异常、议价轮次、总价分析及最终选择依据
- 生成供 OA 审核使用的比价报告
- V1 每项物料最终选择一家供应商

完成标准：从多家报价导入、二次谈价、比价选择到生成 OA 比价报告形成完整闭环。

### M7 — 历史沉淀与发布候选版

实现：
- 物料历史采购价
- 物料历史报价
- 每颗物料 × 每家供应商的历次报价历史
- 历次议价轮次与价格变化
- 物料历史供应商
- 历史 RFQ 分配关系
- 历史选择结果
- 基础历史查询
- 物料价格趋势、物料×供应商报价历史、议价变化分析
- 历史采购价与历史报价对比
- 历史供应商参与/报价覆盖分析
- 上线前历史数据迁移执行、校验与迁移报告
- 区分 legacy 导入数据与上线后原生 SRM 数据
- 离线构建包
- 公共仓库数据安全检查
- 核心回归测试

完成标准：完成一次 RFQ 后，其数据可直接辅助下一次 RFQ；上线前历史采购/询价/报价数据在证据允许的范围内完成迁移并可查询分析。

以下功能不阻塞 V1：

- 在线报价
- 复杂审批

- 拍卖/竞价

## 5. 关键验收规则

### 多对多分配
新增供应商必须是追加关系，不得覆盖既有供应商。

### Coverage
低于 100% 时允许继续生成询价单，仅生成已分配部分。

### 数据追溯
询价明细、供应商询价单、返回报价、标准化报价和最终选择之间必须可追溯。

### 报价原始数据
标准化不得覆盖或销毁导入原始值。

### 大数据量
业务规则不设置固定条数上限。页面使用分页、虚拟滚动、筛选和批量处理，避免一次渲染全部记录。

### 离线
核心 RFQ 流程在断网环境下可完整运行。

### 公开仓库
自动化测试和演示只能使用合成数据，不允许提交真实业务数据。

## 7. 开发顺序

不要先把所有页面全部做完。

推荐顺序：

```text
M0 交互原型
↓
M1 数据基础
↓
M2 RFQ
↓
M3 双向分配
↓
M4 询价单
↓
M5 报价导入
↓
M6 比价选择
↓
M7 历史与发布
```

其中 M0、M3、M5 是返工风险最高的阶段。M0 应提前用虚构数据验证 M5 的报价回收导入交互，但真正的 Excel 解析、模板保存、标准化和持久化仍在 M5 实现。


## 8. V1 PDF 图纸 / 技术文档实施原则

图纸能力已进入 V1 主流程，不再作为 V1 之后的可选增强。

第一阶段以 PDF 为正式目标格式，并考虑多页 PDF。

交互目标：
- 物料清单显示第一页缩略图、PDF 标识和页数
- 点击后在当前应用内预览
- 支持上一页/下一页、页码、缩放、适应宽度/整页
- 一颗物料有多个 PDF 时可在预览器中切换文档
- 采购员无需退出 SRM 即可查看图纸

数据和生成规则：
- 支持一物料关联多个 PDF
- 保存版本/修订信息和有效状态
- M4 按供应商分配范围自动收集相关 PDF
- 生成前检查缺失图纸
- RFQ 生成时保存当时发送附件的快照，后续图纸升级不得改写历史 RFQ

正式离线版优先采用本地打包的 PDF 渲染组件。DWG/DXF 等 CAD 原生格式暂不阻塞 V1。


## 9. 通用交互约束

- 所有加入工作范围的操作，原则上必须有对应的移出/删除能力；审计不可删除的数据除外。
- 删除时必须明确提示关联影响。
- 所有通用数据表字段默认具备字段级模糊搜索能力；新增的可配置字段自动继承。
- 表结构不得以 M0 演示字段为最终标准，正式开发前以 ERP 字段、导入映射和采购业务字段共同确定。


## 10. 本轮 M0 通用交互补充

### 剪贴板录入
- 支持中英文逗号、分号混用
- 支持换行与 Tab 分隔；普通空格不作为字段分隔符，避免拆分“304 不锈钢”等字段值
- 必须先解析预览再确认写入

### 搜索
- 输入过程中不自动搜索、不重绘页面
- 支持多个字段先分别输入条件
- 点击“搜索”后统一按多条件执行
- 不同字段条件默认 AND 组合

### 清单选择
凡具备多选能力的清单统一提供：
- 全选（当前筛选结果全部）
- 本页全选
- 反选（当前筛选结果全部反转）
- 本页反选
- Shift 连选

### 翻页
所有分页业务清单统一提供：
- 上一页 / 下一页
- 数字页码
- 当前页高亮
- 大页数省略显示

### 字段值批量更新
支持两种方式：
1. 选中记录后，将指定字段统一写入同一个值；
2. 导入更新表，根据指定关键字段匹配记录，再批量更新目标字段。

正式版需增加更新预览，并区分匹配成功、未匹配、重复关键值和格式错误。

### 字段维护归属
字段定义新增/删除、类型、ERP 映射等结构性配置进入“系统设置”。
RFQ 日常业务页面只负责字段值录入、查询与更新。


## 11. M0 报价回收导入与轮次验证

M0 增加“报价回收导入”页面，重点验证交互，不承担正式 Excel 解析和持久化。

支持：
- 单条报价输入
- 剪贴板批量粘贴
- CSV/TXT 导入
- Excel 导入流程演示
- 导入预览与物料/供应商匹配检查
- 导入后逐行修改
- 报价轮次新增与确认
- 上轮价格、本轮价格、价格变化展示
- 明确记录“沿用上轮价格”

报价轮次按“RFQ × 供应商”建立：
- 第 1 轮 = 初始报价
- 第 2 轮 = 二次谈价
- 后续可继续新增轮次
- 新轮次永不覆盖旧轮次
- 后轮允许只包含部分物料
- 后轮缺失物料不自动视为价格不变
- 采购员明确确认后，才可将缺失项记录为“沿用上轮价格”
- 同价再次报价时，仍保存为新轮次，降价幅度显示为 0

只有已确认轮次进入报价比较的有效报价逻辑。M5 再实现真实 Excel 映射模板、原始值保留、持久化和修改审计。


## 12. 比价报告与报价覆盖检查分工

### 比价报告

比价报告的最终设计、预览与生成归入 M6「比价与选择」。

但不等到 M6 才考虑数据。各阶段职责如下：

- M0：验证报告所需数据是否完整，包括报价轮次、上轮/本轮价格、降价金额与幅度、未报价/不供货、覆盖异常、最终选择与非最低价原因等。
- M5：确保报价导入与标准化能稳定产生上述结构化数据，并保留原始报价和异常信息。
- M6：正式设计比价报告版式、字段展示、预览和导出，形成供 OA 审核使用的报告文件。

### 报价回收覆盖检查

每个报价轮次保存“本轮应报价物料范围”快照，并以此与实际回收内容比对。

至少区分：
- 已报价
- 明确未报价
- 不供货
- 漏报：本轮应报价但回收数据中完全缺失
- 多报：回收了本轮范围以外的物料
- 重复：同一物料在一次回收中重复出现

首轮默认应报价范围等于该供应商询价单范围。
后续轮次可以是部分议价，因此必须使用该轮次自己的应报价范围，不能简单拿完整 RFQ 作为判断基准。

M0 先验证覆盖统计、异常项目清单和确认前警告；M5 再实现正式 Excel 导入、映射失败诊断、异常处理与持久化。


## 13. 阶梯价格处理

阶梯价格不单独建立一套报价流程，而作为“供应商 × 报价轮次 × 物料”报价明细上的可选结构。

M0 验证：
- 普通单价与阶梯价共用同一条报价记录
- 阶梯结构包含数量起点、数量终点（可为空表示以上）和单价
- 报价导入预览能识别阶梯价
- 导入后可修改阶梯价格
- 比价时根据 RFQ 需求数量自动选取适用档位
- 比价页面标记“阶梯 N 档”
- 轮次比较使用相同 RFQ 数量下的适用价计算涨跌
- 原始完整阶梯继续保留

M5 正式实现不同供应商 Excel 阶梯价格式的字段映射与标准化，包括多列、多行等形式。

M6 比价报告同时展示：
- 本次 RFQ 数量
- 用于比较的适用档位价格
- 完整阶梯价格明细

不能只保存或只展示最终计算出的适用单价，否则会丢失供应商原始报价条件。


## 14. 上线前历史数据迁移原则

上线前历史补录不是让采购员重新“演一遍”过去的采购流程，而是按现有证据能支持到什么层级，就导入什么层级。

### 只有 ERP 订单历史
导入为历史采购/订单事实，例如日期、物料、供应商、数量、单价、订单号等。
不能因为存在订单就虚构历史询价或历史报价。

### 有历史询价/报价证据
在原始询价表、供应商报价、邮件附件等证据可支持时，再导入历史询价/报价事实。

如果历史轮次无法判断：
- 标记为 legacy / 未知轮次
- 不人为猜测“第 1 轮、第 2 轮”

### 每次迁移应保留
- legacy 标记
- 来源类型
- 来源文件/证据引用（如有）
- 迁移批次号
- 导入时间
- 原始值
- 映射/标准化结果
- 未匹配、重复和异常日志

历史补录数据与系统上线后的原生数据必须可区分，但在字段可比时应能一起用于历史价格和供应商分析。
