## 一、范围和验收目标

> <sub>1. Scope and completion gate</sub>

**必须交付：** 可打开的离线 SRM、经可靠性检测的本地自动保存、版本化全量结构化 JSON 备份、可预览且可回滚的恢复、原 M0 核心流程无回退、可移植到服务器的数据模型与读写接口。

> <sub>Deliver offline SRM, validated local autosave, complete structured-data JSON export, previewed atomic restore with rollback, M0 compatibility, and server-portable storage contracts.</sub>

**明确不交付：** 多采购员实时协同、账号登录、自动 NAS/OneDrive 备份、正式服务器部署、真实银行子表导入、Excel/PDF 通用内容识别、OA 流程、真实 ERP API。原始邮件/PDF 文件本体不包含在结构化 JSON 备份内。

> <sub>Out of scope: multi-user live collaboration, authentication, unattended NAS/cloud backups, production server, bank account import, universal document extraction, OA or ERP API. Binary source evidence is excluded from JSON backups.</sub>

**基线：** `main` 上已批准的 M0（合并提交 `f330de5`）。只允许从已经批准的主线创建新的 M1 **开发草稿分支**，建议 `draft/m1-offline-persistence`；未获再次明确批准不得合并 `main`。M0 已有测试及历史业务规则必须继续通过。

> <sub>Baseline is the approved M0 on main at merge commit f330de5. Create a dedicated M1 draft branch and do not merge into main without explicit new approval.</sub>

## 三、先锁定的业务实体与数据契约

> <sub>3. Canonical business contracts before storage</sub>

- **Workspace**：工作空间 ID、名称、`schemaVersion`、应用版本、`revision`、创建/修改时间；每个工作空间独立保存和备份。

> <sub>Independent workspace identity, schema version and optimistic revision.</sub>

- **MaterialMaster**：以 ERP `存货编码` 为主档业务键，遵循已核实字段名；`参考编码1`/`参考编码2` 不合并；**M0 演示种子不能自动导入**。

> <sub>Preserve ERP inventory identity and separate reference codes; demo data is excluded by default.</sub>

- **Counterparty / SupplierRole**：ERP `往来单位编码` 和 `供应商编码` 分别保存并建立身份映射；同一往来单位可以同时有客户/供应商身份。

> <sub>Separate counterparty and supplier-role keys; support dual roles.</sub>

- **RFQHeader / RFQRevision / RFQLine**：可无项目，以 RFQ 流水号组织；`RFQ Line ID` 是稳定询价行 ID，与存货编码不同；发布后修改必须新版本。

> <sub>Stable RFQ line identifiers and immutable issued revision snapshots.</sub>

- **Assignment**：RFQ 行—供应商身份多对多；保留分配与本轮应报价范围快照，Coverage 不足 100% 仍可生成。

> <sub>Many-to-many assignments with frozen round scope; incomplete coverage remains allowed.</sub>

- **QuoteRound / QuoteRevision / QuoteLine / PriceTier**：报价轮次、修订号、报价状态、适用单价、交期、MOQ/MPQ 以及证据引用；确认后不可原位覆盖。

> <sub>Versioned quote records, tiers and provenance references; confirmed history is immutable.</sub>

- **AwardDecision**：报价行来源 ID、人工选定供应商、非最低价原因和待复核状态；后续报价不清除旧选择。

> <sub>Preserve selected quote references, non-lowest reasons and review markers.</sub>

- **EvidenceReference**：证据类型、原文件名、相对/外部定位标识、时间和校验摘要（若可取得）；不假装已经备份原始二进制文件。

> <sub>Evidence metadata and locator only, not guaranteed binary retention.</sub>

- **ImportBatch / AuditEvent**：导入来源、别名映射、确认人、时间、校验结果、修改前后业务状态的关联键；不能记录可公开的真实报价内容。

> <sub>Import provenance and changes without leaking sensitive quote values into GitHub logs.</sub>

M1 首批只实施与询价核心功能有关的字段；220 个 ERP 模板字段保留完整字段字典，银行信息、联系方式、数据协同设置仅保留实体关联结构和匿名测试样本，不要求当前导入或展示真实值。

> <sub>Implement the core purchasing fields first. Preserve all 220 template labels in the dictionary, while deferring real contact, banking and integration child-table content.</sub>

## 五、明确禁止的危险捷径

> <sub>5. Prohibited shortcuts</sub>

- **禁止：**直接 `JSON.stringify(assignments)` 导出 Map 为空对象，或把未报项金额设为 0。

> <sub>Do not lose Map data or fabricate zero-price quotes.</sub>

- **禁止：**在未完成 `indexedDB` 写事务之前显示“已保存”，或静默忽略失败。

> <sub>Never acknowledge saving before an actual successful transaction.</sub>

- **禁止：**用同一可编辑对象存草稿和已确认报价；新轮报价把旧人工定标原因清空。

> <sub>Keep confirmed history immutable and preserve prior manual award reasons.</sub>

- **禁止：**浏览器打开 HTML 时自动初始化 1200 条演示物料并加入正式库。

> <sub>Never auto-import synthetic M0 seed into real workspaces.</sub>

- **禁止：**把 JSON 备份描述为“包括原始邮件、PDF、图纸”。

> <sub>JSON evidence references do not contain original attachment binaries.</sub>
