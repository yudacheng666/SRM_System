## 2. 浏览器批注处理
## 2. Browser annotation resolution

1. 物料、供应商等通过主数据唯一键自动补齐已进入需求与 M1–M3 计划，M0 不伪造正式 ERP 连接。
1. Unique-key autofill for item/supplier master data is planned for M1–M3; M0 does not simulate a production ERP connection.

2. 物料列表的 RFQ Line ID、物料编码、图纸拆分为独立列，消除表头错位。
2. RFQ Line ID, item code and drawing now occupy separate aligned columns.

3. 默认新增时间倒序，列标题按钮可排序，Shift+点击支持多字段优先级排序。
3. Item lists default to newest-first; column-header buttons sort and Shift+click adds priority-ordered sort keys.

4. 图纸预览独立于物料编码列。
4. Drawing preview is now separate from the item-code column.

5. 物料粘贴第一行为表头且精确包含“物料编码”，随后数据按标题而非固定列位置解析。
5. Item pastes require a first-row header with exact “物料编码”, then map data by header names rather than positions.

6. 在字段筛选表头添加搜索/清空按钮，支持 Enter；其余搜索区增加清空条件。
6. Column filters now include Search/Clear and Enter-to-search; other search areas include clear actions.

7. 物料清单增加取消选择；其他已有临时勾选区保留清空选择，供应商关系勾选不因清空而丢失关联。
7. Item lists now support Clear Selection; existing temporary selections remain clearable without removing real supplier assignments.

8. 第 N 轮报价中的 Revision 统一显示“第 M 版”，内部仍保留不可覆盖的版本编号。
8. Quote Revision is displayed as “Version M” within “Round N”, while its immutable internal revision number remains.

9. 增加当前供应商、当前轮次漏报 CSV 导出，包含物料及 RFQ Line ID 等追溯字段。
9. Missing lines can be exported as a supplier/round-scoped CSV with item and RFQ Line ID tracing fields.

10. 同编码且业务属性兼容可自动合并数量和保留原始来源；冲突仅在采购员明确确认后独立保留，取消不会改变数据。
10. Compatible same-code items combine quantity while retaining sources; conflicts remain separate only after buyer confirmation, and cancellation leaves data unchanged.

11. 报价状态统一显示中文“正常报价、明确未报价、不供货、待检查”。
11. Quotation statuses now display readable Chinese equivalents for quoted, explicit no-quote, cannot-supply and needs-review.

12. 错误数据能区分状态错误、无适用阶梯价、缺失报价行身份，未直接写入有效报价。
12. Invalid data distinguishes status errors, unmatched tiers and missing row identity, and is not silently committed as valid quotation.

13. 报价粘贴也改为第一行标题、第二行数据，优先 RFQ Line ID，缺失时仅以唯一物料编码回退。
13. Quote pastes now use header/data rows, prefer RFQ Line ID and allow item-code fallback only for unique matches.

## 3. 核心回归测试（35 项通过）
## 3. Core regression checks (35 passed)

JavaScript 整体语法检查通过；HTML 元素 ID 无重复。
Whole-page JavaScript syntax passed; HTML element IDs had no duplicates.

验证了 RFQ Line ID、物料编码、图纸三列独立，以及搜索、清空、版本标签、漏报导出入口均存在。
Verified separate RFQ Line ID/item code/drawing columns and Search/Clear, version-label and omission-export controls.

物料导入验证了列标题乱序、Tab 复制、空字段不左移、精确主键标题必需、数量 abc/0 拒绝、带引号逗号、重复标题拒绝。
Item-import tests covered reordered headers, tab-delimited paste, empty cells, exact key-header enforcement, rejection of abc/zero quantities, quoted commas and duplicate header rejection.

报价导入验证了列标题乱序、缺状态但有价格可正常报价、价格和状态均缺失时待检查、缺少报价身份标题拒绝、CSV 引号转义及中文状态显示。
Quote-import tests covered reordered headers, price-without-status default, price/status-both-missing review state, missing quote key header rejection, CSV quotes and Chinese status labels.

兼容物料自动合并；单位冲突进入人工确认；已有供应商分配不能静默合并；默认最新行优先展示。
Compatible items merged; unit conflicts required review; allocated items were protected from silent merge; newest-first ordering passed.

阶梯价按 RFQ 数量选档，无适用档返回空值，重叠档位报错。
Tiered prices resolved by RFQ quantity, unmatched quantities returned no price, and overlapping tiers were rejected.

漏报 CSV 构造、显式搜索/清空，以及取消前 N 物料/供应商比价限制经源码结构检查确认。
Missing-line CSV construction, explicit Search/Clear and removal of first-N comparison limits were verified at the source-structure level.

This round did not run browser-driven mouse/keyboard automation, so layout, download behavior and end-user ergonomics still require Codex/Playwright and buyer validation.

All data remains synthetic; code and documents were updated only on the draft branch, without merging main.
