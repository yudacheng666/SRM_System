# 20261013 SRM 离线原型数据范围与开发顺序 V2
# 20261013 SRM Offline Prototype Data Scope and Development Order V2

## 已确认的事实 / Confirmed Facts

- SRM 尚未正式投入使用，不存在需要保护或迁移的历史业务数据。
- SRM has not entered production and has no historical business data requiring migration or retention.
- 浏览器 IndexedDB 数据与导出的 JSON/ZIP 均为原型测试数据，可以不迁移到新的 SQLite 数据库。
- Existing IndexedDB records and exported JSON/ZIP files are prototype test fixtures and need not be migrated into SQLite.
- 测试数据可以重新生成；无需开发旧 JSON/ZIP、浏览器缓存或测试库的自动迁移程序。
- Synthetic test data can be regenerated; no automatic migration tool is required for legacy JSON/ZIP or browser records.
- 对 `main` 分支的保护规则不变；新开发仅在独立分支进行。
- The rule protecting `main` remains; develop on isolated branches only.

## 直接采用目标方案 / Direct Target Architecture

- 新版原型直接以本机 SQLite 为业务数据主存储，不以 IndexedDB 作为正式存储或故障回退方案。
- The new prototype uses local SQLite as the primary business store; IndexedDB is neither the primary nor a fallback store.
- 图纸、原始报价附件、聊天截图、电子邮件证据等保存到独立的本机文件目录，由 SQLite 记录哈希和关联。
- Store drawings, original quote attachments, screenshots and email evidence in a local asset folder, with hashes and links in SQLite.
- 前端通过本机 HTTP API 访问数据，不需要公司服务器、门户、统一登录和多用户权限。
- Browser UI accesses data through loopback HTTP API; no enterprise server, portal, SSO or multi-user permissions now.
- 测试与调试数据不得写入 GitHub 仓库；仅使用虚构示例。
- Do not commit test/runtime data into GitHub; use fictitious examples.

## 重新调整的工作计划 / Revised Delivery Plan

| 顺序 / Order | 任务 / Task | 验收标准 / Acceptance |
|---|---|---|
| S2 | 本机 SQLite + HTTP API 基础 / SQLite + local API | 已建立基础，仍需完整实机验收 / Foundation present; real-device verification pending |
| S3 | 现有业务动作直接接入 SQLite / Wire existing business actions to SQLite | 断网可用、关闭与重新打开后数据不丢失 / Offline; data survives browser and service restart |
| S4 | 图纸与报价凭证直接落盘 / Persist drawings and provenance assets | 文件与物料/报价关联正确，重启后可读 / Correct linked originals and restart-read |
| S5 | 完整备份与恢复 / Full backup and restore | SQLite + 全部原始附件恢复且校验一致 / Restore DB and all originals, verify integrity |
| S6 | UI 信息架构和交互设计 / UI information architecture and interaction | 采购员实际操作确认，功能保留 / Buyer confirms workflow without feature loss |
| S7 | 离线验收与 IT 交接 / Offline validation and IT handoff | 完整测试、源代码、文档、安装说明 / Tests, source, docs, launch guide |

- **删除原计划中“旧浏览器 IndexedDB 数据迁移”“旧 JSON/ZIP 导入迁移”两项任务。**
- **Remove “legacy browser IndexedDB migration” and “old JSON/ZIP migration” from the plan.**
- 原来 JSON/ZIP 可以保留为测试参考；其内容不作为正式历史业务数据。
- Existing JSON/ZIP may remain as test references, not formal historical business records.
- 从目标版开始，界面不能在 SQLite API 不可用时静默改用浏览器存储；要明确报错并阻止假保存。
- In the target version, the UI must not silently fall back to browser storage when SQLite API is unavailable; fail clearly.
- 新库从空白建立，仅导入新的虚构种子数据进行验收，待功能稳定后再由用户手工录入或导入实际业务数据。
- Start a clean database, seed only synthetic fixtures for testing, then later allow the buyer to enter real data after validation.

## 仍需开发的实际功能 / Remaining Engineering Scope

- 统一询价列表/选择当前询价和新增询价的 SQLite 后端逻辑。
- A SQLite-backed RFQ list, active selection, and creation workflow.
- 业务数据操作的自动保存策略、写入错误提示和版本冲突防护。
- Business-change persistence, visible write failures, and revision conflict handling.
- 真实附件存储、引用校验、删除策略及完整备份恢复。
- Real assets, reference checks, removal policy, and complete verified backup/restore.
- UI 整体设计与浏览器运行验收。
- Full UI redesign and real-browser acceptance tests.

## 非目标 / Out of Scope

- 历史测试数据兼容与自动迁移。
- Legacy synthetic test data compatibility or automatic migration.
- 服务器部署、公司办公门户、SSO、ERP 接口和生产级权限。
- Server deployment, portal integration, SSO, ERP integration and production-grade permissions.
