**日期：2026-10-22；状态：设计候选（待产品审核）；仅文档，不修改生产功能。**
**Date: 2026-10-22; Status: design proposal pending product review; documentation only, no product code changes.**

**基线：draft/20261013-m1-storage-ui-audit；SHA：f117cf3ca512a4ca7e1eec505b5e28744159343f。**
**Baseline: draft/20261013-m1-storage-ui-audit; SHA: f117cf3ca512a4ca7e1eec505b5e28744159343f.**

**现有版本已完成 UI V3.1 接入和 C03–C09 分范围独立业务验收；本次整改是 Windows 人工试用中的“易用性/信息架构”后续工作，不推翻已有业务验收。**
**The existing version integrated UI V3.1 and passed scoped independent C03–C09 business acceptance; this proposal follows Windows hands-on UX feedback and does not invalidate those functional results.**

## 0. 决策摘要 / Decision summary

- **优先重构报价回收和比价议价的工作流；同时统一 RFQ 上下文、保存状态、备份/业务导出、物料与图纸的入口规则。**
- **Prioritize quote intake and comparison/award workflows; also standardize RFQ context, save status, backup vs business export, and item/drawing entry points.**
- **问题不是十几个独立样式缺陷，而是功能入口随历史增量开发叠加，使业务决策顺序、技术管理操作和说明文字混在同一屏幕。**
- **The issue is not a dozen independent CSS bugs; incremental features have mixed decision sequence, system maintenance actions, and instructions on the same screens.**
- **本阶段不改报价计算、SQLite 模型、历史轮次、唯一 RFQ 行身份、PDF 存储、Excel 内容或 S4 恢复安全；只实施呈现层与明确受控的交互。**
- **Do not change price calculations, SQLite schema, quote history, immutable RFQ line identity, PDF storage, Excel content, or S4 restore safety; implementation concerns presentation and controlled interactions only.**
- **采取一个集成开发 PR、分段提交和开发者 CI；功能整体稳定后才交 Codex TEST-ONLY 做针对性的真实业务验收，不因驱动错误重新开整套测试。**
- **Use one integrated implementation PR with incremental commits and developer CI; hand off once to Codex TEST-ONLY for targeted GUI acceptance after integration is stable, without repeatedly retesting the entire product for driver mistakes.**

## 3. 信息架构目标 / Target information architecture

### 3.1 顶部唯一上下文栏 / One authoritative workspace header

**固定显示：当前 RFQ 号（可复制）、工作类型、主保存状态、最近保存时间；侧边栏和内容区不再重复整段 RFQ 编号。**
**Show current RFQ ID (copyable), workspace mode, primary save status and last-save time once; do not repeat the full RFQ identifier throughout sidebar and content.**

**主状态只允许：已保存、正在保存、未保存修改、保存失败/冲突、只读；附加的 SQLite/备份版本放“状态详情”里。**
**Primary statuses: Saved, Saving, Unsaved changes, Save failed/conflict, Read-only; move SQLite and backup revisions to a Status Details disclosure.**

**真正保存失败/冲突时必须醒目且阻止危险操作；不能把“已保存”写成虚假的静态标签。**
**Save failure or conflict remains prominent and blocks unsafe operations; never invent a static "saved" label.**

### 3.2 侧边导航与入口 / Navigation and entry points

**采购主流程：询价项目 → 物料与图纸 → 供应商分配 → 报价回收 → 比价议价；每个页面保留真实业务入口。**
**Primary procurement flow: RFQ projects → Items & drawings → Supplier allocation → Quote intake → Comparison & award; retain all real actions.**

**导出供应商询价单在供应商分配/询价项目的业务上下文内；内部比价报表在比价议价区；完整备份与恢复仅在“数据与备份”管理入口。**
**Supplier RFQ exports stay near supplier allocation/project context; internal comparison reports stay with comparison; full backup/restore stays in Data & Backup administration.**

**导出不应与“恢复当前记录”和“旧版 JSON+PDF ZIP”同列为常用业务按钮；低频旧版操作留在兼容工具折叠区。**
**Do not present export beside current-record restore and legacy ZIP as equally frequent business actions; legacy actions belong in an expandable compatibility section.**

**保持 sidebar 已有 tab 委托、项目切换、历史数据选择的原事件契约；不要新增另一份 JS 业务状态。**
**Preserve existing sidebar tab delegation, RFQ switching and history event contracts; do not duplicate business state.**

### 3.3 页面总规则 / Cross-page rules

**每页仅一个 H1/H2 业务标题、一个简短行动说明、一处主操作；说明文案默认折叠为“规则说明”，不占用整屏。**
**Each page gets one business title, one short action sentence and one primary action; longer rule text moves into optional help.**

**1024px 宽可见关键操作且无遮挡；1366×768 是默认布局目标；1600×900 利用横向空间而不人为拉高行距。**
**Key controls remain reachable at 1024px; optimize the default for 1366×768; use extra horizontal space at 1600×900 without bloating row heights.**

**按钮不是靠统一大蓝块表示“重要”；主要操作单一高亮、次级采用普通轮廓、删除/恢复采用危险语义。**
**Avoid equally prominent blue blocks; use one emphasized primary action, secondary outlines, and destructive semantics for delete/restore.**

**单条录入、剪贴板导入、文件导入为一个“录入区”内的切换方式，不把三个高度相同的大盒子并排。**
**Single entry, clipboard and file import become modes within one intake area, not three equally prominent tall cards.**

**顶端轮次状态采用“第 N 轮 / 第 M 版 / 已确认或草稿”，不能把“轮次”和“版本”混称。**
**Show Round N / Revision M / Confirmed or Draft, never conflate negotiation rounds with correction revisions.**

**覆盖摘要常态一行呈现；若漏报、重复、额外或未报价则对应值可点击进入错误列表。**
**Show coverage as one compact line; missing, duplicate, extra or no-quote counts expand to their respective problem lists.**

**明细主表默认 7 列左右；较长规格、MOQ、交期、备注、来源及分段价转移至行详情；提供详细列模式，不删除字段。**
**Default to roughly seven primary columns; move long specification, MOQ, lead time, notes, provenance and tier breakdown to row details, with a full-column mode so no fields are lost.**

**表格正文目标 13–14px、辅助说明 12px；默认行高目标 40–44px，随折行只在必要时增加；禁止靠 10px 小字换密度。**
**Target 13–14px body type, 12px secondary type and approximately 40–44px compact rows, increasing height only as needed; never achieve density using illegibly small text.**

**数量为当前正式询价数量，主表显示“适用单价”而非把原始阶梯字符串当唯一价格；详情同时保留各档原文。**
**Quantity comes from the active RFQ; display effective applicable unit price in the main table while preserving all original tier bands in details.**

### 4.2 “刷新当前明细”的精确定义 / Exact semantics of Refresh Current Details

**按钮文案：“刷新显示”，旁边显示仅本页数据视图更新，不意味着从 SQLite 覆盖草稿。**
**Button label: Refresh display; clarify that it refreshes the current view, not overwrites drafts from SQLite.**

**默认仅基于当前内存工作区状态重新计算表格/覆盖率/价格差异；不请求保存、不新建报价、不改变轮次或版本、不修改时间戳。**
**By default, recompute rows, coverage and price deltas from current in-memory workspace state; do not save, create a quote, switch round/revision or change timestamps.**

**刷新必须保留：当前供应商/轮次/版本、分页位置、筛选、选中行、未提交的文件导入预览、沿用上轮预览、输入框草稿、滚动位置；确有冲突时明确拒绝刷新并解释。**
**Refresh must preserve supplier/round/revision, pagination, filters, selection, uncommitted import preview, carry-forward preview, unsaved form drafts and scroll position; if preservation is unsafe, refuse explicitly with a reason.**

**不能把现有 renderQuoteRound() 原样绑定到刷新按钮：它目前会直接清空 carryForwardPreview 和部分临时 UI。**
**Do not wire the current renderQuoteRound() directly to refresh: it currently clears carryForwardPreview and transient UI.**

**后续如需要“从已保存记录重新载入”，必须作为独立危险操作，读取最新 SQLite 版本并检查 dirty/修订冲突；明确确认后才允许覆盖当前未保存状态。**
**Any future Reload saved record must be a separate guarded operation with SQLite revision and dirty/conflict checks, never a silent overwrite.**

**导入确认、逐行修改、新版确认与轮次切换本身应自动更新可见数据，刷新只是补充操作。**
**Import confirmation, row editing, revision confirmation and round selection should automatically update the view; refresh is a fallback.**

**现有 #srmV31DecisionBoard 可复用，但应成为唯一顶部决策摘要；#quoteModeNotice 和冗长规则文本移入“报价口径说明”。**
**Reuse #srmV31DecisionBoard as the single decision overview; move quote-mode notes and long rules into a Scope & Rules disclosure.**

**#commonScopePicker 不再抢占逐物料比价的注意力；放在筛选/分析区，采购员明确勾选两家及以上才计算可比较总额。**
**Move #commonScopePicker into filters/analytics rather than dominating line awards; calculate directly comparable totals only after the buyer explicitly selects at least two suppliers.**

**#quoteTable 保留一个物料一行、多供应商横向对照；冻结物料身份列，长行备注只在单元格详情展开，避免堆叠三行或四行元信息。**
**Keep a line-by-supplier comparison matrix with sticky identity column; show long terms and notes on demand rather than three or four text rows in every cell.**

**报价单元格默认展示价格和关键状态；选择后的人工确认来源必须明确区别于系统最低价建议，且并列最低全部高亮。**
**Default quote cells show price and critical state; explicit buyer decisions must remain distinct from system suggestions, with all tied-lowest offers highlighted.**

**非最低价确认必须弹出现有理由对话框，不能因视觉调整而跳过；报价变更后需复核原人工决定。**
**Preserve mandatory justification for genuinely non-lowest awards; quote changes must flag prior manual awards for re-review.**

**历史采购价未接入时不显示充满一整列的“未接入”；应以一次性明显但不阻挡的全局提示标明不可用于当前计算。**
**When historical purchase price is unavailable, avoid a full repeated "not connected" column; show one truthful global notice and exclude it from calculations.**

**理论最低组合、同范围组金额、已人工定标金额分别命名且不相加、不伪装成某一家供应商总报价。**
**Name theoretical lowest combination, shared-scope totals, and confirmed manual award totals separately; never add or label them as a single supplier's offer.**

**金额计算继续按已验收“适用阶梯价 × 询价数量”的人民币分精度与有效共同口径；不在 UI 改造中擅自增加税、汇率或采购单位换算。**
**Keep the accepted effective tier price × RFQ quantity in CNY cents and valid shared-scope boundaries; do not introduce unvalidated tax, FX or purchasing-unit conversions during UI work.**

### 5.2 必须维持的比较语义 / Immutable comparison semantics

- **已确认报价参与比价；草稿不可冒充已确认记录。**
- **Only confirmed quotes participate; drafts must not appear as confirmed responses.**
- **同编码不同规格须通过 RFQ Line ID 区分。**
- **Different specifications with the same item code require immutable RFQ Line IDs.**
- **未报价、漏报、不供货、未分配分别呈现，均不得当零价格。**
- **No-quote, missing, cannot-supply and unassigned are distinct, and none becomes a zero price.**
- **一物料允许多家供货方参与，但 V1 最终人工定标每物料一家；并列最低任何一家不要求非最低理由。**
- **Multiple suppliers may quote each line, but V1 selects one buyer-awarded supplier per line; any tied-lowest quote requires no non-lowest justification.**
- **不同供应商自身有效报价金额不可直接排名；只有选择共同有效范围才比较同口径总额。**
- **Never rank unmatched own-scope totals; compare aggregate totals only for an explicitly selected common valid scope.**
- **已确认轮次和修订只读；原始报价证据、邮件/附件、截图/PDF 与手工输入来源不丢失。**
- **Confirmed rounds and revisions remain immutable, and quote provenance/evidence from emails, attachments, screenshots/PDFs or manual entry is retained.**
- **供应商外发资料只含该供应商可见的项目、字段、PDF，不含内部报价、其他供应商、JSON 数据或定标理由。**
- **Supplier-facing packages reveal only assigned items, allowed fields and PDFs, excluding other suppliers, internal quotations, JSON state and award reasons.**
- **备份 ZIP 与导出 Excel 的真实内容及文件命名保持现有安全要求，禁止设计改造时重写或变相绕过。**
- **Keep backup ZIP and exported Excel content/names under existing safety constraints; the design must not bypass or silently rewrite them.**

## 6. 物料、图纸、管理页：统一但分批实施 / Related screens: unified vision, phased implementation

**物料清单：默认行可读，编码/名称/规格同一主行内分层显示；表头冻结与横滚明确，分页数量显示清晰。**
**Item table: readable default rows, hierarchy within code/name/spec, clear sticky headers, horizontal scroll and pagination.**

**图纸关联：操作依次为“选择 PDF → 匹配预览 → 处理多候选/未匹配 → 确认建立关联 → 保存”，保留原 PDF 原件与版本。**
**Drawing flow: Select PDFs → Preview matches → Resolve ambiguous/unmatched → Confirm associations → Save; preserve original PDF bytes and versions.**

**默认不要展开全部图纸高级操作；独立展示批量匹配与单条追加，说明文案移到展开帮助。**
**Do not expand all advanced drawing controls by default; separate batch matching from single attachment, and collapse long guidance.**

**数据管理：S4 完整备份和恢复成为独立安全工作流；恢复仅空白数据、警示说明和拒绝原因必须显著。**
**Administration: S4 backup/restore is an isolated safety flow, with clear empty-target-only restrictions and rejection explanations.**
