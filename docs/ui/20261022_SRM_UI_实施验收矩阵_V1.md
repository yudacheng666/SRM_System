## 2. 功能“不变”基准 / Business invariants that must remain unchanged

| 不变量 / Invariant | 实现中禁止的退化 / Forbidden regression | 证据类型 / Evidence |
|---|---|---|
| 已确认报价不可改写 / Confirmed quote immutable | UI refresh/编辑不能覆盖旧版 / No refresh or edit rewriting old revision | SQLite 修订快照 + GUI / SQLite snapshots + GUI |
| 轮次与同轮版本分离 / Round vs revision | 切换标签不能新建版本 / Navigation cannot create revisions | 历史条数前后对照 / Before/after count |
| 区分漏报/不供货/未报价 / Distinct missing statuses | 不能以 0 元参与比价 / No zero-price substitution | 行状态 + 比价数字 / Status and amounts |
| 阶梯适用单价 / Applicable tier price | 不能用首档价代替适用档 / Do not assume first tier | 真实数量与阶梯案例 / Real quantity/tier fixture |
| 最低价并列 / Tied lowest | 任何并列最低不应要求高价原因 / No reason demanded for tied-lowest | 真实定标对话框 / Award GUI |
| 非最低价理由 / Higher-price reason | 无原因不能确认 / No confirmation without reason | 阻止/允许两条路径 / Block and accept |
| 系统建议与人工选择分离 / Suggestion vs explicit award | 建议不算正式定标 / Suggested != confirmed award | #srmV31DecisionBoard + 状态 / DOM and state |
| 同范围总额 / Comparable aggregate | 供应商报价项目不同不可直接排名 / Own-scope totals not ranked | 2家共同有效子集 / Selected common scope |
| 完整保存确认 / Save ack | 点击只读/导航不能虚假 dirty；失败不能显示 saved / No false dirty; no false saved | SQLite ACK + UI / Database + UI |
| 导出与 S4 / Export and S4 | ZIP/PDF/SQLite 不得泄露、损坏、错误覆盖 / No leakage, corruption, unsafe overwrite | ZIP 内容 + 恢复 409 / ZIP and HTTP409 |
| 行主键 / RFQ line identity | 相同编码不同规格不能混为同一行 / No ambiguity on duplicate code | 双同编码不同规格数据 / Duplicate code fixture |

## 3. 开发者自动化测试矩阵 / ChatGPT developer test matrix

### A. 报价回收 / Quote intake

- **DEV-Q01：** 在 1366×768、1600×900 查看真实已确认的第 2 轮报价；紧凑表的普通 1 行预计 40–44px（有明确换行的特例应测量记录），字号不低于 13px，金额不被裁切。
- **DEV-Q01:** With real confirmed Round 2, target ~40–44px for ordinary compact rows at 1366×768 and 1600×900 (measure justified wrapping exceptions), >=13px body text, no clipped amounts.
- **DEV-Q02：** 7 列左右默认核心列；详情中完整保留 RFQ Line ID、规格、交期、MOQ、分段价、来源、备注、凭证信息，紧凑模式与详细模式互切不写 SQLite。
- **DEV-Q02:** Roughly seven default core columns; details preserve RFQ line, specification, lead, MOQ, tiers, source, notes and evidence; switching density does not write SQLite.
- **DEV-Q03：** 进入第 2 轮草稿，填入尚未确认报价及“沿用上轮”预览，按刷新显示后数据、焦点、页码、供应商/轮次/版本不变，SQLite revision 不变。
- **DEV-Q03:** In a Round 2 draft with unconfirmed import and carry-forward preview, refresh preserves state, focus, page, supplier/round/revision, and SQLite revision.
- **DEV-Q04：** 真实保存冲突/未保存编辑下的“重新读取已保存记录”不得默默覆盖；用户拒绝后草稿与未保存状态保持。
- **DEV-Q04:** Reload saved data must never overwrite unsaved/conflicted drafts silently; cancel preserves draft and dirty state.
- **DEV-Q05：** 确认报价后自动刷新可见明细；已确认版本只读，修改需创建正确同轮新版。
- **DEV-Q05:** Confirmed import auto-updates rows; confirmed history read-only, corrections require an actual new revision.

### B. 比价与定标 / Comparison and award

- **DEV-C01：** 有 8 条有效物料、3 家供应商但未人工选择时，显示“有效报价物料 8、人工已选 0、待决定 8”（如有实际不可报价行按状态另计）；无“全部已定标”假象。
- **DEV-C01:** With eight quotable lines and three suppliers but no manual awards, show eight valid, zero manually awarded, eight pending (subject to actual invalid lines); never imply all awarded.
- **DEV-C02：** 系统建议最低价展示但不修改 manualAwards；人工选择会更新状态及 SQLite，切回页面仍一致。
- **DEV-C02:** Lowest-price suggestion does not populate manualAwards; explicit selection updates and persists correctly.
- **DEV-C03：** 供应商甲 ¥75/乙 ¥75 两个并列最低都可直接选择；选择 ¥77 的供应商需填写非最低原因。
- **DEV-C03:** Either ¥75 tied-lowest supplier can be chosen directly; choosing a ¥77 offer requires non-lowest justification.
- **DEV-C04：** 共同报价组选不足 2 家不能显示可比较总额；若两家无共同有效报价则显示“0 项”但不伪造 ¥0.00。
- **DEV-C04:** With fewer than two chosen suppliers no comparable total; with zero shared eligible lines report zero lines without fabricated ¥0.00.
- **DEV-C05：** “某供应商自身有效报价金额”与“逐物料理论最低组合”必须不同名、不同提示，不可显示为同范围排名；缺价不乘零。
- **DEV-C05:** Distinguish own-scope totals from theoretical line-level minimum; never rank incompatible scopes or multiply missing prices by zero.
- **DEV-C06：** 页面 UI 按钮不能绕过已存在的非最低价理由、价格变更复核、报价锁定或成本口径。
- **DEV-C06:** UI controls must not bypass reasons, quote-change re-review, immutability or price scope logic.

### C. 工作区、图纸、导出与可读性 / Workspace, drawings, exports and readability

- **DEV-W01：** 正式 RFQ 顶部编号与状态有唯一主要展示区域；页面切换前后保持一致；错误/冲突优先提示。
- **DEV-W01:** One authoritative RFQ identifier/save-state region remains consistent across pages; conflict/failure overrides success.
- **DEV-W02：** 默认不展示长段 SQLite 技术信息；点“状态详情”后可以查看版本和备份来源，不虚构时间。
- **DEV-W02:** Do not default to long SQLite diagnostics; status details retain true revision/backup timestamps without invention.
- **DEV-W03：** 业务询价 ZIP、内部比价 Excel 入口分别贴近对应业务步骤，S4 及兼容 JSON 仅在管理区，但原完整文件路径/内容仍可用。
- **DEV-W03:** Business exports are contextual and S4/legacy JSON remain administrative; all underlying files still work.
- **DEV-W04：** PDF 唯一/多候选/未匹配明确区分，确认前无正式关联，确认后 SQLite + PDF 不变；缩进引导不改 PDF 真值。
- **DEV-W04:** Unique/multiple/unmatched drawing paths stay explicit; no pre-confirm association, post-confirm persistence unchanged.
- **DEV-W05：** 不在正常页制造水平遮挡、超出视口的主按钮、两层滚动互相捕获；1024、1366、1600 三宽度快照与几何检查。
- **DEV-W05:** No clipped primary actions or trapped nested scrolling at 1024, 1366 or 1600; collect screenshots and geometry.
- **DEV-W06：** 表格横向滚动时物料列保持可见，焦点态清晰；不依赖颜色区分“已选择”和“最低价”。
- **DEV-W06:** Keep item identity visible when horizontal scrolling; keyboard focus and text labels distinguish selected vs lowest, never color alone.

## 6. 合并与回滚门槛 / Merge and rollback gates

- **门槛 1：** 设计方案经用户明确接受，才从开发基线新建产品功能分支；设计 PR 保持 Draft，不代表已实施。
- **Gate 1:** Obtain explicit design acceptance before starting a product branch from the current baseline; design PR remains Draft and is not implementation.
- **门槛 2：** 每一阶段 ChatGPT 修改产品、补充真实 Chromium + SQLite 回归及定向 DOM/视觉检查；任何 CI 失败先修复，不交给 Codex“代修”。 
- **Gate 2:** For each phase ChatGPT changes code, adds real Chromium + SQLite tests and targeted DOM/geometry checks; fix CI failures before Codex.
- **门槛 3：** 只有准确最终 SHA 的相关 GitHub CI 全部 SUCCESS 且没有新的阻断缺陷，才发一条 Codex TEST-ONLY 定向验收指令。 
- **Gate 3:** Issue one targeted Codex TEST-ONLY task only when CI on the exact latest SHA is green and no blocking defects remain.
- **门槛 4：** Codex 出具一份独立 Draft 证据 PR，保存实际操作、文件内容、截图和原始失败；测试驱动错误允许一次有记录的修正重测，但产品安全风险立即停止相关范围。
- **Gate 4:** Codex creates one Draft evidence PR preserving actual actions, file contents, screenshots and raw failures; allow one documented driver correction, stop on genuine product safety risks.
- **门槛 5：** ChatGPT 复核 CI/证据并给出合并建议；开发基线/main 只有用户明确批准才能合并。
- **Gate 5:** ChatGPT independently reviews evidence and recommends; merge into baseline/main only with explicit owner approval.
- **回滚：** 改造只能新增/重排视图组件，不修改存储 JSON/API 合约；出现持久化、报价金额或导出隔离异常时立即撤回受影响 UI 提交。
- **Rollback:** Keep persisted JSON/API contracts unchanged; revert the affected UI commits if persistence, price totals or export isolation regresses.

## 7. 审核清单 / Design approval checklist

- [ ] 认可“报价回收 → 比价议价”先于其他页面的优先级。 / Prioritize quote intake and comparison first.
- [ ] 认可紧凑报价主表 + 行详情 + 可选详细列模式。 / Accept compact primary rows with details and optional full columns.
- [ ] 认可“刷新显示”不触发 SQLite 重载、不丢草稿。 / Accept view-only refresh that never silently reloads SQLite.
- [ ] 认可比价的三层结构：决策概览、逐物料比价定标、按口径金额分析。 / Accept overview, line awards and scope-aware analytics.
- [ ] 认可保留所有已验收的安全与业务逻辑，统一开发 PR + 一轮有证据的 Codex 定向验收。 / Preserve all accepted safeguards and use one implementation PR plus one scoped Codex UAT.
- [ ] 认可工作区状态与备份/图纸的后续统一标准。 / Accept shared standards for status, backup and drawings.

**全部勾选前不把设计文档改动解释为生产版本升级；任何新增需求需要先检查其是否会改变业务不变量。**
**Until approved, a document change is not a product release; assess any new request against the business invariants before implementation.**
