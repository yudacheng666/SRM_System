# 20261013 SRM S3 Local SQLite and PDF Trial Acceptance V1

## 版本及限制 / Version and Limitations

- 本文适用于 `draft/20261013-m1-storage-ui-audit` 下的 `prototype/m1-lite`。
- This checklist applies to `prototype/m1-lite` on `draft/20261013-m1-storage-ui-audit`.
- 当前仅虚构数据测试；没有旧业务数据，也没有旧 JSON/ZIP 迁移需求。
- This is a synthetic-data-only trial with no historical data or migration requirement.
- 本机测试以 `run_local.bat` 启动，完整业务 UI 必须从 `http://127.0.0.1:8765/` 访问。
- Launch with `run_local.bat` and access the business UI at `http://127.0.0.1:8765/`.
- **报价原始证据附件、自动保存和全量恢复尚未完成；本版不得作为正式生产环境。**
- **Original quote evidence files, autosave and full restore are not finished; this is not production software.**
- 本次只实现 S3 的业务保存、历史索引与 PDF 图纸持久化；UI 重新设计另行验收。
- S3 covers workspace persistence, RFQ index and PDF originals; redesigned UI will be accepted separately.

## A. 基本启动 / Basic Launch

- [ ] 双击 `run_local.bat` 后，浏览器打开本机 S3 原型，没有跨站访问问题。
- [ ] Launch through `run_local.bat` and verify same-origin local UI startup.
- [ ] 打开 `/api/health`，返回 `stage: S3` 和 `backend: sqlite`。
- [ ] Confirm `/api/health` reports `stage: S3` and `backend: sqlite`.
- [ ] 直接双击 `index.html` 不应允许创建正式保存的工作区。
- [ ] Direct `file://` HTML must not allow successful persistent business storage.

## B. 业务数据存储 / Business Persistence

- [ ] 新建一笔空白询价，添加虚构物料和供应商，执行保存，出现明确的 SQLite 成功信息。
- [ ] Create an RFQ with synthetic items/suppliers and verify acknowledged SQLite save.
- [ ] 修改数量或供应商关联后再次保存，版本递增且内容可重新读取。
- [ ] Edit item quantity/assignment; save again; revision increments and data reloads.
- [ ] 关闭浏览器和本机服务并重启，先前内容仍在；无浏览器 IndexedDB 依赖。
- [ ] Restart browser and server; data survives independently of IndexedDB.
- [ ] 新建第二笔询价并保存，第一笔依然可以通过历史列表切回。
- [ ] Save a second RFQ and switch back to the first using history.
- [ ] 两个浏览器标签分别编辑，旧版本保存必须提示冲突，不能静默覆盖。
- [ ] Stale edits from a second tab must be rejected with visible revision conflict.
- [ ] 停止本机服务后尝试保存，不得显示“已保存”，须明确报错。
- [ ] Stop the local service; writes must fail visibly and never fake success.

## C. PDF 图纸 / PDF Drawings

- [ ] 先保存新询价，再上传不超过 12MB 的测试 PDF。
- [ ] Save the new RFQ before uploading a synthetic PDF no larger than 12 MiB.
- [ ] 单条及批量图纸导入、文件名匹配、手工确认和版本关系均按原业务逻辑操作。
- [ ] Exercise one-at-a-time and batch PDF import, matching proposals, manual confirmation and revisions.
- [ ] 关闭浏览器并重启后，原始 PDF 仍可打开且 SHA-256 校验通过。
- [ ] Restart the browser and verify the original PDF loads and passes checksum validation.
- [ ] 文件扩展名假冒 PDF、非法内容和错误哈希应被拒绝。
- [ ] Reject fake PDF extensions, invalid content and checksum mismatches.
- [ ] 不应能跨询价访问未关联的 PDF 原件。
- [ ] PDFs must not be readable from another RFQ without the matching asset registration.

## D. 导出及限制 / Exports and Limits

- [ ] 可以导出单笔/全部结构化 JSON；仅作为当前记录导出，不要求导入旧测试 JSON。
- [ ] Export single/all structured JSON; legacy fixture import is intentionally unsupported.
- [ ] 图纸 ZIP 导出包含对应原始 PDF，不可遗漏损坏或不存在的文件。
- [ ] PDF ZIP export must include original PDFs and must not silently omit broken originals.
- [ ] 数据库单独备份明确标注不包含 PDF，不能把它视为完整恢复包。
- [ ] DB-only backup must clearly exclude PDF and must not be called full recovery.
- [ ] 当前 UI 无旧 JSON/ZIP 恢复入口；正式完整备份与恢复放在 S4。
- [ ] Legacy JSON/ZIP restore is disabled; verified full restore belongs to S4.

## E. 验收结论 / Sign-off

- Static JavaScript check: all five inline scripts passed syntax compilation; end-to-end browser flow remains untested.
- 使用隔离 Python 测试环境复核过本机保存、两笔询价切换、冲突拒绝和 PDF 落盘/读回等接口行为。
- Isolated Python checks exercised save, two-RFQ switching, conflict rejection, and PDF disk write/read.
- **Windows 实机、完整采购业务流程、数据异常恢复、自动保存与报价附件归档：未验收。**
- **Windows device, full buyer journey, crash recovery, autosave and quote-evidence archive: not accepted yet.**
- 人工验收结论应由采购员测试后填写：通过／问题清单／未测。
